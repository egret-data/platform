# What actually holds each `compare: "error-class"` entry to account.
#
# error-class comparison is a FREE PASS: the entry matches on any failure at
# all, so it is born matching, never enters baseline.txt, and can never fail.
# `error-class.txt` makes ADDING one a visible diff. This file makes each one
# ANSWERABLE: it names, per id, the thing that would notice if egret stopped
# refusing -- or says plainly that nothing does yet, and whose job that is.
#
# Until now the pairing was a convention written in prose. Tasks 6-8 will add
# more entries (Task 8's whole deliverable is refusals), and a convention
# nobody checks is not a constraint. `tests/oracle.rs`'s
# `every_error_class_entry_is_paired_with_something_that_can_fail` asserts this
# file against `error-class.txt` in BOTH directions, checks every named test
# exists, and checks every `baselined` claim -- so an entry added without a
# pair fails the suite by name.
#
# Format: `<corpus id> <justification>`. `#` starts a comment.
#
#   test:<name>       a `#[test] fn` in this crate that asserts egret's OWN
#                     message for that input. The strongest form: it fails if
#                     the refusal turns into a success OR changes meaning.
#   baselined         the id is ALSO in baseline.txt, so it is not born
#                     matching at all -- egret succeeds where Kestra throws and
#                     the ratchet is already policing it. Verified against
#                     baseline.txt, not taken on trust.
#   unported:<task>   nothing is ported behind it. The entry matches only
#                     because egret says "unknown function", exactly the
#                     hollow pass B5 warns about. Named so it is a declared
#                     debt with an owner rather than an omission. The set of
#                     these is ALSO pinned, as a const in tests/oracle.rs, so
#                     a new one cannot be added quietly here.
