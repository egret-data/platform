# WHAT EACH FILTER RETURNS: all 63 filters the engine binds, crossed with a
# fifteen-input matrix, asked through Kestra's OWN `className` filter.
#
# W2a. W2 Task 8's fix round recorded the collection class as fourteen corpus
# entries and said in its own report why that number could not be trusted:
# "those are the pairs I thought to cross -- nothing enumerates the return
# collection of the other 40 filters." A hand-written list produced "three",
# then "five". This file is the enumeration that replaces the list, and
# `collection-pairs.txt` beside it is what the enumeration was for.
#
# The instrument is the engine itself: `className` is a Kestra filter, so
# `{{ (<input> | <filter>) | className }}` asks Pebble what its own types are.
# No reflection and no bytecode -- one `host.Oracle generate`.
#
# Format, tab separated:
#
#   filter  input  expr  kestra  egret  reason
#
# `input` names a binding in the matrix: `l` a three-element list, `l1` a
# ONE-element list, `ll` a nested list, `m` a two-key map, `m1` a ONE-key map,
# `s` the string `a,b,c`, `sc` the single character `,`, `n` the integer 42,
# `nul` an explicit null, `el` an empty list, `em` an empty map, `dt` an ISO
# instant, `ns` the string `42`, `b` a boolean, `b64` a base64 string.
#
# `dt`, `ns`, `b` and `b64` exist because without them `date`, `dateAdd`, the
# four `timestamp*`, `number`, `abs`, `numberformat` and `base64decode` answer
# nothing but an exception and their return class is unmeasured -- the first
# cut of this file had that hole and 279 of its 756 cells were exceptions.
#
# `l1` and `m1` exist because **the LENGTH is part of this task's rule and the
# matrix carried only two of its three buckets.** `Collections.reverse` calls
# `set` no times below two elements and `List.sort`'s default calls it once per
# element, so 0, 1 and "many" are three different behaviours. The first fix
# round's own defect was reachable only at 0 and 1, and the propagation fixture
# built on a matrix with no length-1 member saw ONE of its five expressions;
# with `l1` it sees five. A dedup key that cannot express a distinction cannot
# preserve a representative of it.
#
# `sc` exists because `",".split(",")` is the EMPTY array, and it is the only
# way this matrix reaches length 0 of the `Array` kind. Round 2 also stopped
# deriving the bucket from the input BINDING and started deriving it from the
# measured length of the produced value: the binding is exact for a list or a
# map and meaningless for a string, so every `split` result had been landing in
# the "many" bucket whatever its actual length, and the `Array` kind existed at
# one length only in a file whose header claimed three. Filling it found a live
# over-acceptance in `default` -- see the fix-round section of `README.md`.
#
# `kestra` and `egret` are the rendered class name, or `error`. Values are
# JSON-escaped so a tab can never be one. `expr` is the rendered expression,
# verbatim, and the probe and answer maps are keyed by IT rather than by an id
# derived from the row -- see `collection-pairs.txt` for what that closed.
#
# A row whose two columns AGREE must carry `-`, and a row whose columns
# DIFFER must carry a reason. `runners::filters::the_return_classes_match_the_engine`
# asserts every egret cell by rendering it, and
# `..::the_return_class_fixtures_kestra_column_is_the_harnesss_own_answer`
# asserts the kestra column against `fixtures/return-classes.answers.json`, so
# a hand-edited fixture fails and a Kestra bump moves it visibly. See
# `oracle/README.md`, "Regenerating the answer fixtures".
#
# WHAT IT FOUND, and it is not what the corpus said. Eight filters return
# something that is not a plain `java.util.ArrayList`:
#
#   split       [Ljava.lang.String;                           an ARRAY, not a List at all
#   chunk       com.google.common.collect.Lists$RandomAccessPartition
#   flatten     java.util.ImmutableCollections$ListN
#   keys        java.util.ImmutableCollections$ListN (list/array) / LinkedHashMap$LinkedKeySet (map)
#   values      java.util.LinkedHashMap$LinkedValues
#   slice       java.util.ArrayList$SubList
#   escapeChar  java.util.HashMap (map input)
#   merge       java.util.HashMap (map) / java.util.ArrayList (list)
#
# But eight is the answer to the CLASS question, not to the behaviour one:
# `slice`'s `SubList` is a mutable `List` and every consumer accepts it, and
# `escapeChar`/`merge` return a Map whose only observable difference is its
# ORDER (already recorded). The producers that make the NEXT filter behave
# differently are five -- `keys`, `values`, `flatten`, `chunk`, `split` -- and
# that half of Task 8's number was right. `collection-pairs.txt` is where the
# behaviour is measured, and it puts the CONSUMER side at eight, not six.
#
# One more divergence off the collection axis, recorded here: `first`/`last`
# on a String return a `java.lang.Character` where egret has no character type
# separate from a one-character string.
#
# And one CORRECTION rather than a divergence, which the first cut of this file
# reported as a third: `timestampMicro` and `timestampNano` really do return a
# `java.lang.String` where `timestamp` and `timestampMilli` return a `Long` --
# but egret answers `java.lang.String` for both too, so the two engines AGREE
# and those rows carry `-`. It corrects the brief's table; it is not a
# divergence, and calling it one was an error of this file's first cut.
