# The REFUSAL SETS: which pattern letters egret actually renders and reads,
# per side, against what the real engine does.
#
# `letter-counts.txt` covers only whether a pattern COMPILES. `z` compiles and
# then refuses at render; `w` compiles and then refuses at parse. That layer had
# no fixture, and it is where `v` and the four legacy zone ids lived -- both
# found by a reviewer running probes, neither by the suite. Prose does not fail.
#
# `tests` in `runners::javafmt` asserts this file BIDIRECTIONALLY:
#
#   - a letter egret refuses that the engine accepts fails, naming the letter;
#   - a letter egret accepts that the engine refuses fails, naming the letter;
#   - a row whose two outcomes DIFFER must carry a reason, and a row whose
#     outcomes AGREE must not -- so a divergence cannot be added silently and a
#     refusal cannot claim to be one when it is not;
#   - every letter that compiles per `letter-counts.txt` must appear on BOTH
#     sides, so a new letter cannot enter the alphabet undeclared.
#
# **The two sides differ deliberately and the difference is encoded, not
# flattened**: egret refuses three letters when writing and eight when reading.
# W2 Task 5's fix round 2 made the sets identical and wrote down "a letter egret
# can write, it can read"; fix round 3 broke that on purpose for the five
# locale-resolved letters, and this file is where that decision now lives.
#
# Format: `<side> <pattern> <engine> <egret> <sample> <reason>`, tab-separated.
#   side     `format` or `parse`
#   engine   what io.kestra:core:2.0.0-rc13 does, MEASURED through the harness
#   egret    what egret must do
#   sample   parse side only: the text after `2024-03-09 14:25:36 | `, which is
#            the engine's OWN output for that letter on that instant -- a round
#            trip, so a row cannot fail for want of a well-formed input
#   reason   `-` when the two agree; why they differ otherwise
#
# The five locale-resolved samples are formatted WITHOUT an explicit locale, so
# the round trip is self-consistent on the harness machine (`en_VN`,
# Monday-first). That is exactly the fact that makes them divergent: under
# `locale='en'` the engine would write a value its own parser then rejects.
#
# **Regenerate only from the harness, never by hand** -- the same rule
# `golden.json` and `letter-counts.txt` carry.
