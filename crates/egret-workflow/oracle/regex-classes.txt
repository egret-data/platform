# JAVA REGEX vs egret: what each construct actually ANSWERS, per subject.
#
# A 265-probe sweep of Java's pattern language against the RAW `regex` crate
# found 101 divergences, and the dangerous half raised nothing on either side:
# `\d` matched an Arabic-Indic digit, `\v` did not match a newline, `(?i)k`
# matched the Kelvin sign, `c$` did not match before a trailing newline. That
# is why `runners::javare` exists.
#
# This file is that sweep's answer layer, committed so the claim "nothing is
# silent" can be RE-CHECKED rather than re-asserted. Four tab-separated
# columns plus a reason:
#
#   pattern <TAB> subject <TAB> java <TAB> egret <TAB> reason
#
# `java` is `true`/`false` (the value `regexMatch` renders) or `error`, taken
# from the Java harness. `egret` is the same, or `refused` -- egret declining a
# construct Kestra accepts, which is a DIFFERENT thing from an error and is
# spelled `Unsupported regex` rather than `Invalid regex`.
#
# `runners::javare::the_regex_classes_match_the_engine` asserts it
# bidirectionally, exactly as `refusal-sets.txt` is asserted:
#
#   - a row where the two columns differ must carry a reason, and a row where
#     they agree must not, so a divergence cannot be introduced silently and a
#     refusal cannot claim to be one when the engine refuses too;
#   - **a row whose `egret` column is `true` or `false` and differs from
#     `java` fails outright** -- that is the silent class, and there is no
#     reason that makes one acceptable.
#
# Escapes are JSON's (`\t`, `\n`, `\u00e9`), because a tab-separated file
# cannot carry a literal tab and a subject can.
