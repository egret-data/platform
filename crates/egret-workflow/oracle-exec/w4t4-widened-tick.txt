WHY THIS FILE EXISTS
--------------------
`worker::tick`'s doc and this directory's README both state a ruling — one
handler result per transaction — and quote two numbers against the alternative:
the ratchet the widened tick reaches (140, banking three entries) and the crate
run under the widened tick. Neither number is reproducible from the shipped
tree, because the shipped tree does not contain the widened tick. This file is
the raw output of those runs, plus the exact mutation that produces them, so
that a reader can check the ruling instead of believing it. It is the same kind
of artifact as `harvest-run.txt`: a measurement whose subject no longer exists
in the checkout.

RUN 3 — THE REAP COUNTER-CONFIGURATIONS, both disciplines
--------------------------------------------------------
Fix round 1. The first report's cost 1 was measured in ONE configuration — a
registry that reaps every live lease from inside the SECOND handler — and that
is the arrangement most favourable to the shipping tick, because the first
handler's result has already committed when the lease goes. The review asked for
the counter-configurations. They are below, one scratch database per row
(`#[sqlx::test]`), because `claim` and `reap` are GLOBAL: a first attempt ran all
five configurations against one database and each row claimed the previous row's
leftovers, which showed up as tick counts (`Ok(3)`, `Ok(4)`) larger than the
whole flow's runnable set. That instrument defect is recorded because the
contaminated numbers looked entirely plausible.

The flow is a `Parallel` of two `core.log.Log` leaves, `a` and `b`; six rounds

RUN 4 — THE FENCE HOLE THE WIDENED TICK COULD SHIP, AND NOTHING SEES IT
----------------------------------------------------------------------
This is the ruling's PRIMARY cost, and it is a measurement rather than an
argument. `persist`'s doc records a four-mutation table proving that the two
lease fences — the `outputs` write's and the state UPDATE's — are ALTERNATIVES,
each sufficient on its own, so that no single-hunk mutation of either can be
seen to fail. That table was taken against a transaction that releases exactly
ONE lease. The widened tick releases n.

The experiment puts a defect in the surviving alternative that can only manifest
at n > 1, on top of the widening:

  F1  delete the `outputs` fence outright from the widened `apply_outcomes` --
      which the four-mutation table says is survivable, because `persist`'s
      fence is the other alternative:
      -             WHERE id = $2 AND claimed_at = $3",
      +             WHERE id = $2 AND $3 IS NOT NULL",
      - and the `if hit.rows_affected() == 0 { LeaseLost }` check with it

  F2  make `persist` fence only the group's FIRST lease. Byte-for-byte
      equivalent at n == 1; at n > 1 every other member's state write is
      unfenced, so a reaped worker can commit a terminal over its replacement --
      W3b's Critical, exactly:
      -             let lease = release.iter().copied().find(|l| l.run_ix == ix as i32);
      +             let lease = release.first().copied().filter(|l| l.run_ix == ix as i32);

RESULT: the whole crate is GREEN but for the ordering guard, which fires for the
ordering and not for the fence.

    fn parallel_two(id: &str) -> String {
        format!(
            "id: {id}\nnamespace: t\ntasks:\n  - id: p\n    type: io.kestra.plugin.core.flow.Parallel\n    tasks:\n      - id: a\n        type: io.kestra.plugin.core.log.Log\n        message: hi\n      - id: b\n        type: io.kestra.plugin.core.log.Log\n        message: bye\n"
        )

    /// A registry that reaps every live lease from inside ONE named handler,
    /// either on every call or only on the first.
    struct Reaper {
        pool: sqlx::PgPool,
        from: &'static str,
        once: bool,
        fired: Mutex<usize>,
        seen: Mutex<Vec<String>>,
    }
    
    #[async_trait::async_trait]
    impl Registry for Reaper {
        async fn run(&self, task: &TaskInput) -> egret_core::Result<Outcome> {
            self.seen.lock().unwrap().push(task.task_id.clone());
            let should_reap = {
                let mut fired = self.fired.lock().unwrap();
                let yes = task.task_id == self.from && (!self.once || *fired == 0);
                if yes {
                    *fired += 1;
                }
                yes
            };
            if should_reap {
                reap(&self.pool, std::time::Duration::ZERO)
                    .await
                    .expect("reap");
            }
            Ok(Outcome::success())
        }
        async fn cancel(&self, _task: &TaskInput) -> egret_core::Result<()> {
            Ok(())
        }
    }
    
    async fn one_config(pool: &sqlx::PgPool, name: &str, from: &'static str, once: bool) {
        egret_test_db::assert_database_url_is_exported();
        let db = Db { pool: pool.clone() };
        let (ws, _user) = common::seed_workspace(&db).await;
        let ex = start_execution(pool, ws, None, &parallel_two(name), serde_json::json!({}))
            .await
            .expect("start execution");
        let reg = Reaper {
            pool: pool.clone(),
            from,
            once,
            fired: Mutex::new(0),
            seen: Mutex::new(Vec::new()),
        };
        let mut ticks = Vec::new();
        for _ in 1..=6 {

                Ok(n) => format!("Ok({n})"),
                Err(_) => "Err(LeaseLost)".to_string(),
            });
            if matches!(r, Ok(0)) {
                break;
            }
        }
        let states: Vec<(String, String)> = sqlx::query_as(
            "SELECT task_id, state FROM workflow.task_runs WHERE execution_id = $1 ORDER BY run_ix",
        )
        .bind(ex)
        .fetch_all(pool)
        .await
        .expect("states");
        let seen = reg.seen.lock().unwrap().clone();
        println!("CONFIG {name}");
