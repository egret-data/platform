## Findings
(append one line per surprise, with the file/line in site-packages that explains it)

- T2 smoke (run, thread): the whole chain worked with NO change to `proxy.py` — `PY pid=97346 viewer=alice sql=SELECT 1 AS n` and `SQLCELL viewer=alice`; marimo accepted the proxy's `Authorization: Bearer pod-secret` on HTTP and on the WS upgrade (`marimo/_server/api/auth.py:77-86`), and `--base-url /r` needed no path rewriting.
- T2: `DBAPIEngine.is_compatible` accepted the plain `Connection` unchanged — it only duck-types `cursor/commit/rollback/close` (`marimo/_sql/engines/dbapi.py:95-107`); `mo.sql(..., engine=db)` then ran through egret's gateway as the viewer.
- T2 Step 7a holds: `Session.create` is keyword-only (`*,` at `marimo/_session/session.py:99-101`), and its only caller passes `mode=`/`sandbox=` by name (`marimo/_server/session_manager.py:368-397`), so the kwargs patch is sound.
- T2 Step 7b is FALSE: `IPCKernelManagerImpl` has no `_sandbox` attribute in 0.25.0; without `[venv] path` it always builds a uv `NotebookSandbox` (`marimo/_session/managers/ipc.py:331-431`). Adapted by patching `ipc._get_venv_config` (`ipc.py:65`) to return `path = sys.prefix` in `--process-mode ipc` only — NOT via `marimo.toml`, because a configured venv beats the sandbox (`ipc.py:333`) and would silently turn `--process-mode sandbox` into the ipc variant. (ipc variant not yet exercised; that is Task 3+.)
- T2: in single-file `marimo run` the AppHost path is never taken (`isolate_apps` requires multi-file, `marimo/_server/start.py:307`), so `sandbox=True` on `Session.create` really does select the IPC kernel (`session.py:160`).
- T2: `XDG_CONFIG_HOME` is the LAST place marimo looks for config — a `.marimo.toml` in cwd, any parent, or `~` wins first (`marimo/_config/utils.py:69-120`). None exists on this machine; a pod must guarantee that too.
- T2: `NotebookWorkspace.load` runs twice per edit open — once for the index page (`marimo/_server/api/endpoints/assets.py:387` → `session_manager.py:191`) and once for the session (`session_manager.py:353`) — so the storage patch re-fetches the draft and rewrites the file each time (logged "EgretStorage bound to probe rev 1" ×2).
- T2: the edit launcher asks for draft `xss`, which does not exist yet (fake egret 500s on unknown ids, `fake_egret.py:97`); `entrypoint.py` now skips missing drafts with a log line.
- T2: each WS close revokes the session token (`proxy.py` ws_relay), so one host-page load = one ticket = one token, revoked when the iframe goes away (3 loads → 3 `token_revoked` events).
- T2 (test harness, not marimo): the RED run failed with `AttributeError: module 'egret_marimo' has no attribute 'connect'`, not `ModuleNotFoundError`, because Task 1's `egret_marimo/.gitkeep` made the directory an implicit namespace package.
- T3 Q1: header reached the right kernel on every read incl. reactive re-runs (14 gateway queries, alice/bob never crossed, no rejects); both sessions ran in pid 544 (thread mode), so per-session identity rests on the header/ContextVar, not process isolation.
- T3 Q5 (automated Playwright, not manual): the SQL-cell engine dropdown lists `db` only once the cell defining it has run (before: only "DuckDB (In-Memory)"); after run-all, `db` is listed and auto-selected on a new SQL cell. Default SQL cell needs duckdb+sqlglot installed to run.
- T4 Q2 (thread): 4 sessions, `distinct_pids=1`, max 17.71 s (5.24 s alone, 16.6 to 17.7 s for 3 concurrent; an earlier run before the hold rerun gave 12.07 s max, the JSON was overwritten); server rss 103.8 MB with 4 sessions open. Automated Playwright probe (`q2_process.py`), single run, macOS dev laptop, unmeasured load.
- T4 Q2 (sandbox): `marimo run --sandbox` on a single file does NOT give a process per session. `run_in_sandbox` (`marimo/_cli/cli.py:1251`, `_cli/sandbox.py:461`) re-execs the whole server inside a uv env with `--sandbox` stripped, so the inner server is thread mode: `distinct_pids=1` (online 17.18 s max, offline with `UV_OFFLINE=1` and warm cache 12.0 s max). It also re-execs from `sys.argv[1:]`, so `entrypoint.py` must set `sys.argv = ["marimo", *argv]` first (else `error: unexpected argument '--mode'`), and the sandbox env holds only marimo: the app's imports (`httpx`, `polars`, `duckdb`, `sqlglot`) must be PEP 723 deps (first try: `ModuleNotFoundError: No module named 'httpx'`, `results/q2-sandbox-attempt1-error.txt`). `uv add --script` also rewrites the app file's header. Offline works only because the script env was cached. Scope: `probes/q2_process.py` is an automated Playwright probe; single run per mode on a macOS dev laptop under unmeasured load; concurrent spawns contend (thread mode shows the same concurrency penalty). The offline result held only with a warm uv cache (cold-cache offline untested).
- T4 Q2 (ipc): the forced-IPC variant works, `distinct_pids=4`, max 32.9 s (cold first session 13.2 s; three concurrent spawns ~32 s), log banner `Using configured venv: .../.venv/bin/python`, no uv build. Step 7a needed a fix: `Session` is a Protocol with no `create`; the patch target is `session.SessionImpl.create` (`marimo/_session/session.py:91,99`). Scope: `probes/q2_process.py` is an automated Playwright probe; single run per mode on a macOS dev laptop under unmeasured load; concurrent spawns contend (thread mode shows the same concurrency penalty).
- T4 Q2 rss (ipc, 4 sessions): ~80 MB per kernel process (79.9 to 81.3 MB) plus server 77 MB plus an 11.7 MB multiprocessing resource_tracker; thread mode is server 103.8 MB total.
- T4 Q1 in ipc: header still reached the right kernel across the subprocess boundary (alice and bob each on their own pid, 12 gateway queries, no rejects, `results/q1-ipc.json`).
- T5 Q3: round-trip works (draft rev 1 to 2, marker in draft). A stale save gets HTTP 409 `{"detail":"This draft was saved by someone else — reload."}` from `POST /e/api/kernel/save` (2 POSTs, 2 `draft_conflict` events for one ctrl+s attempt) and the author DOES see it: a red "Failed to save" toast with that detail text, and the save button stays yellow (`results/q3-conflict.png`, viewed by agent). Working selectors in headless Chromium: `.cm-content` (last) + `Control+s`. Nothing about the conflict appears in egret's header, and the local buffer keeps the unsaved edit.
- T5 hazard (design point for P3): the storage patch re-fetches the draft and rebinds a fresh revision on EVERY `workspace.load` (2 per editor open, more on reload/second tab/index fetch), so a live editor's held revision is silently reset and a later stale save would succeed, overwriting the other editor. The probe did no navigation between the external PUT and the second save; `storage_binds` in q3.json shows 0 binds after the PUT. Re-fetch-on-load must not reset the revision a live editor holds.
- T6 Q4: author JS DOES execute in marimo 0.25.0 run mode via an `anywidget` `_esm` module (arbitrary JS by design); `mo.Html` is sanitized — a `<script>` and an `<img onerror>` both stayed inert ("pending"). From the widget's apps origin (`apps.egret.localhost:8701`): `parentDoc blocked:SecurityError`, `document.cookie` empty of egret cookies, cross-origin fetch to egret whoami/mutate unreadable (CORS `TypeError`), and `/e` (edit) upstream 401 — a run cookie can't reach the editor (`results/q4.json`). Scope: automated Playwright probe (`probes/q4_origin.py`), single run per cookie mode, HeadlessChrome 136, macOS dev laptop.
- T6 Q4: the ticket is single-use (replay of the redeemed ticket → 403) and the apps proxy refuses a request with no `apps_sid` (→ 401). Scope: automated Playwright probe (`probes/q4_origin.py`), single run per cookie mode, HeadlessChrome 136, macOS dev laptop.
- T6 Q4 (server side, the real surface): a same-site cookie DID ride the cross-origin request — egret logged `whoami` as `alice`, and it received the no-cors `mutate`; with plain cookie names the toss `egret_csrf=evil` reached egret (`raw_cookie` shows **two** `egret_csrf`). No mutate passed CSRF (`ok=false`, `any_mutate_succeeded=false`) because no-cors can't set `x-egret-csrf` and the preflight blocked the header variant. `apps.egret.localhost` and `egret.localhost` are same-*site* (shared registrable domain `egret.localhost`) — prod must put apps on a different registrable site and keep CSRF header-based, not value-based. Scope: automated Playwright probe (`probes/q4_origin.py`), single run per cookie mode, HeadlessChrome 136, macOS dev laptop.
- T6 Q4 (`__Host-`): Playwright Chromium would not store `__Host-` `Secure` cookies over `http://*.localhost` (login 200 but `context.cookies()==[]` → host page "login first"), so the `__Host-` cookie-toss defense could not be exercised on the http dev stack; MUST be redone over HTTPS on kind in P4 (`results/q4-host-prefix.json`). Scope: automated Playwright probe (`probes/q4_origin.py`), single run per cookie mode, HeadlessChrome 136, macOS dev laptop.
- T6 (test harness, not marimo): the proxy process vanished twice between runs. Cause identified: restarting fake egret with `lsof -ti :8700 | xargs kill -9` also matched the proxy's pooled httpx client socket to :8700 (ESTABLISHED, verified: unfiltered `lsof -ti :8700` returned both the egret and proxy pids, `-sTCP:LISTEN` only egret). `servers.sh stop-run` had the same pattern for :2719. Fixed: `stop-run` and the new `restart-egret` kill only the LISTENING pid; after a LISTEN-only egret restart the proxy kept its pid and still relayed. Not a proxy or WebSocket defect.
- T7 Q6: `build_routes("")` yields 107 leaf routes (`results/q6-routes.json`). Blocking by proxy prefix `/terminal,/api/packages,/api/secrets,/api/files,/api/ai,/api/storage,/api/home,/api/kernel/copy,/api/kernel/rename,/api/kernel/install_missing_packages,/api/export/auto_export,/api/export/requirements,/api/lsp` broke nothing: q3 (edit, save, 409) and q1 (run, header per viewer) give the same answers (`results/q3-blocked.json`, `q1-blocked.json`). The editor itself probes `POST /api/packages/sandbox` and `GET /api/lsp/health` on open; both got 403 with no visible effect.
- T7 Q6: `/terminal/ws` opens with the pod token when reached directly on :2718; through the proxy it is 403 on `/e` and `/r` (automated Playwright, `probes/q6_terminal.py`, `results/q6-terminal.json`). `/api/kernel/save` cannot be prefix-blocked (editing needs it) and accepts a `filename`, confined only by marimo's inside-workspace check (`marimo/_server/api/endpoints/files.py:152-180`); `/api/kernel/save_user_config` writes the shared marimo.toml and was left open.
- T7 fix round: a prefix deny-list is only as good as its path normalisation. The first proxy matched `request.url.path` and then httpx collapsed dot segments, so a raw client got `200` from `GET /e/x/../api/packages/list` (also `%2e%2e` and `..%2f` forms); the same forms passed the check on the WebSocket path too but marimo refused the un-collapsed URL (`websockets.exceptions.InvalidStatus`), so no shell was reached (`results/q6-bypass.json`; browsers normalise, so q6-terminal.json could not see it). Fixed by checking and forwarding one value, the raw path (`proxy.py forwarded_path`), rejecting dot segments, `//`, encoded `.` `/` `\` `%` and NUL, matching case-insensitively (`results/q6-bypass-fixed.json`: 0 of 40 variants pass). P4 must match on the forwarded path and should prefer an allow-list.

(`results/s0b-breakdown-*.json`).
