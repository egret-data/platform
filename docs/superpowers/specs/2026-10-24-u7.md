# U7: Alerts and reports UX — fix plan

Package U7 of the Known-issues fix programme. Premise checked on main `837adc16` (demo stack, workspace `docs-sandbox`, as admin, 1440x900 light): KI-038, KI-039, KI-219, KI-220 and KI-221 reproduce; KI-171 partly (the Value column is empty and narrow and its heading sits 0 px from Detail's, but **Started** did not wrap at the time of the check).

| Row | What changes |
|---|---|
| KI-038 | `humanizeCrontab` stays the one formatter for a schedule in the Alerts UI (list, page header, editor). It now also reads hourly (`0 * * * *` → *Every hour at minute 0*), a weekday range (`30 8 * * 1-5` → *Every Monday to Friday at 08:30*), monthly (`0 9 1 * *` → *Every month on day 1 at 09:00*) and yearly (`0 8 1 1 *` → *Every year on 1 January at 08:00*). A shape it cannot say honestly (a minute list, a day-of-month crossed with a weekday, a backwards range) is still shown raw. The editor's preview reads *Runs every day at 09:00 (`0 9 * * *`) in UTC.*, and the raw cron field shows the same line under it when the expression has words. |
| KI-039 | **Don't send when there are no rows** (and its **Delivery** group) is shown for alerts only. A stored value on a report or Data API alert is still sent back unchanged. |
| KI-171 | The run log (dialog and the page's Recent runs) uses the shared `ui/table`: padded headings, State and Started do not wrap, only Detail wraps. A report's log has no Value column. |
| KI-219 | `ConfigTableRow` gets a `more` prop: *Details* holds one short line and the rest opens from an info button (a popover, so keyboard and touch work too). Every Details text over 90 characters in the editor is split that way, and the internal instruction on **Endpoint** is gone. Selects in the Value column fill it; **Condition** is a fixed operator plus a threshold that fills the rest. FE-PAGE-5 says so. |
| KI-220 | The Notification tab is one `Setting | Details | Value` table: a **Deliver to** group with one row per destination and an **Add a destination** row, then **Message**, **Attachment**, **Delivery**. |
| KI-221 | `?section=` keys are the tab labels: `general`, `condition` / `contents`, `schedule`, `notification`. `what` (the old key) still works, and `condition` and `contents` open the second tab on either type. An unknown key opens General with a message naming the sections; choosing a tab writes the label key. |

## Decisions

- KI-221: aliases are not rewritten in the URL on load; the key is replaced when the reader picks a tab. That keeps the message visible for an unknown key until the reader acts on it.
- KI-220: the primary button placement the row mentions is KI-183 (package U8) and is left alone here.
- No migration, no API change.
