# U10: Control Plane, Governance and settings UX — fix plan

Package U10 of the Known-issues fix programme. Premise checked on main `ff03d0f0` (demo stack, workspace `default`, as admin, 1440x900 light): all nine rows reproduce. KI-001 was reproduced against a stock Trino 483 (no `http-server.process-forwarded`): it answers `406 Server configuration does not allow processing of the X-Forwarded-Proto header`, and egret said `engine: http 406 Not Acceptable` (dataset create: 502; connection Test: the row only said *Failed*).

| Row | What changes |
|---|---|
| KI-001 | The Trino connector reads a 406 as the forwarded-header refusal it is and says so: *Trino refused the X-Forwarded-Proto header egret sends over plain HTTP (HTTP 406). Set `http-server.process-forwarded=true` in the coordinator's config.properties, or connect over https.* Every caller (dataset create, SQL Lab, connection Test) gets that text. The connection Test result on Workspace settings shows the outcome's `detail`; it read a `message` field that a test outcome never has, so every failure read *Failed*. |
| KI-007 | Decision D5, labels only: the workspace level says **Connections** (Workspace settings nav and page, the connection pickers of SQL Lab, Datasets, the dataset dialog, Data API and the alert editor); the Control Plane keeps **Engines**. URLs, API paths and field names do not change. A filter that picks an engine *type* (Trino, StarRocks) keeps the word Engine. |
| KI-011 | Test refreshes the connection list, so **Status** and the counts follow the result at once. A new connection is tested right after it is saved (the dialog no longer claims a reachability check on save that the server never did). The count reads *1 connection*. |
| KI-016 | The Control Plane's index and catch-all redirect to absolute paths. A relative `Navigate` from the catch-all resolved against the unmatched URL and appended `workspaces` without end. |
| KI-131 | On the Data page's Permissions tab each grant row has an **Open** link to `/governance/grants/<id>`; grant and rule rows (Permissions, Masks & filters) have labelled **Edit** and **Delete** buttons. The grant page takes the same `?from=data:` way back as the rule page. |
| KI-132 | After **Preview** the grant dialog scrolls its preview panel into view, so the result is on screen without scrolling by hand. |
| KI-203 | In **Grant engine permission** the user and group suggestions sit in the flow under the search field (as a rule's exemptions do), so the open list pushes **Grant** down instead of covering it. The list still stays open after a pick (spec P12, D9a: several picks in a row). |
| KI-204 | Registering an external engine without a profile ends on its **Settings** tab (*Bind a policy profile*), not on Plugin config. Plugin config of an engine with no profile says why in a sentence and offers **Open Settings**; the raw `conflict: …` text is gone. |
| KI-212 | `GET /ws/{ws}/notifications/smtp` and `/slack` answer **204 No Content** when nothing is configured instead of 404, so the Notifications page loads without console errors. A configured channel still answers 200 with its settings. |

## Decisions

- KI-212 changes the API (404 → 204 for "not configured"); the OpenAPI spec and the generated client are regenerated.
- KI-203 keeps D9a (the list stays open after a pick) and moves the list into the flow rather than closing it.
- KI-011: creation still does not check reachability (an unreachable engine can be saved, as before); the page runs the same Test the row button runs, right after the save.
- No migration.
