# U8: Data API and Apps UX — fix plan

Package U8 of the Known-issues fix programme. Premise checked on main `ff03d0f0` (demo stack, workspace `docs-sandbox`, as admin, 1440x900 light). All nine rows reproduce, with two notes: KI-027 now applies to Apps only (the Data API **Versions → Who** shows the email for an admin), and KI-183 has moved: at 1440 px **Create service account** AND **Create endpoint** both sit on the left under the description.

| Row | What changes |
|---|---|
| KI-025 | A client whose expiry is past reads *Expired · expired 9 months ago*; a future one still reads *expires in …*. |
| KI-027 | `AppVersionSummary` gets `published_by_name` (profile name, else email), read in the same statement as the version row (`with_publisher_name!`, the `with_creator_name!` pattern of workflows), so an editor who may not list users sees it too. The Versions dialog shows it; the short id remains only for a deleted publisher. |
| KI-031 | The closed **Database and parameters** strip names its contents: *warehouse · region, limit* (or *No database chosen*, *no parameters*). |
| KI-042 | The 428 of `PUT .../draft` says where the revision comes from (*GET the draft first and send its ETag (also its `revision` field) as If-Match*). Publishing a draft that is still the untouched new-app starter is refused: 409 `{"code":"starter_draft"}`, and the editor names it. |
| KI-176 | `usePublishApp` invalidates the versions query, so an open Versions dialog shows the new version. |
| KI-177 | **Publish** re-reads the app first and publishes the revision it just read (still as `expected_revision`); the toast names it (*Published version 1 from draft revision 3*). |
| KI-182 | The Apps row menu is named per row (*Actions for Revenue explorer*). |
| KI-183 | `ListPageShell`'s title block is `flex-[1_1_20rem]`: a long description shrinks it instead of wrapping the action under it, so every create page has its button top right. |
| KI-184 | The Versions dialog says *restored from v1*. A draft-only app's viewer shows our own sentence, not the server's lower-case detail. |

## Decisions

- KI-025: a revoked client keeps no actions menu. Revoke is its only action, so a menu on a revoked row would open onto nothing; the empty cell is the existing, documented choice (`Clients.tsx`).
- KI-027: the Data API Versions tab is not changed: it shows the email for an admin; for a user who may not list users it still falls back to the short id (recorded, not fixed here).
- KI-031: the strip stays collapsed. The collapse was a measured choice (open, it leaves the SQL editor about 107 px at a 900 px viewport); the summary now carries what the row asked to see.
- KI-042: "starter" is decided from the content (`template::is_untouched_starter`: exactly the template, for no database or any one database name), not from the revision: a duplicate's revision 1 is a real notebook and stays publishable. Restoring a version is not affected.
- KI-177: the guard is kept. A save that lands between the re-read and the publish is still a 409; what went away is the 5 s window of the label.
- `deploy/demo/verify-apps.mjs` drops its two workarounds for KI-176 and KI-177.
- No migration.
