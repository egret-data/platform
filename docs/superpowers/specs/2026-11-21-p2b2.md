# P2-B2 — Trino open-engine per-user baseline (KI-333)

## Premise (re-verified on origin/main 31b679010)

`ir_load::load_infra_inputs` set `delegating` only for engines that pass
`qualifies_for_infra` (provisioned AND jwt/impersonate). `lower_infra` returned
before the three Trino per-user statements (`egret-user-impersonate-self`,
`egret-user-execute-query`, `egret-user-query-timeout`) for `!delegating`. The
red test `an_open_engine_apply_seeds_the_user_baseline_and_no_delegator_grant`
drives the real apply path (`build_provision_req`) for `delegationMode: none`
and found no baseline rows.

## What "open engine" means

`trino_delegated_conn_options` gives an open engine `{}` options and no secret.
`TrinoConnector::new` then uses `auth_user = "egret"` and, with no bearer and
no `impersonate`, `session_user = auth_user`. Every browser user of an open
engine therefore reaches Trino as ONE shared principal, `egret`, sent as
`X-Trino-User`. The Ranger plugin (bound by `ranger_binding` for any bound
profile) checks `impersonate` on `trinouser=<X-Trino-User>`, `execute` on the
query and `alter` on `query_max_run_time` for that principal in every session.

## Decision: approach 1 (seed the baseline), not approach 2

Approach 2 ("don't require it") is not available: the checks are in the plugin,
not in anything egret sends per user, so an open engine cannot opt out without
removing the plugin. The baseline policies use the `{USER}` macro, so for the
shared principal they grant exactly `egret -> egret`, execute, and the timeout
property. They give no cross-user identity or data access (isolation is
unchanged; an open engine has no per-user isolation to weaken). The
delegator grant and admin all-access stay delegation-only.

## Change

- `egret_core::engine_delegation::needs_user_baseline(type, origin)`: a
  provisioned Trino engine, any mode (external engines stay untouched).
- `InfraInputs.user_baseline`; `lower_infra` emits the three statements for
  Trino when `delegating || user_baseline`; the delegator grant additionally
  requires `delegating`.
- `load_infra_inputs` sets it; `infra_services_via` includes such profiles so the
  boot pass converges existing open engines.
- No migration, no API change.

## Out of scope (recorded)

An open engine's profile still gets no admin all-access, so data access for the
shared `egret` principal comes only from compiled grants naming it.
