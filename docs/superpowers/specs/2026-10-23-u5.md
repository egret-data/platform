## KI-065: slug rules and references

- A saved filter keeps its slug when renamed, so existing dashboard URLs (`?region=…`) and `{{region}}` keep working. Nothing about stored dashboards changes.
- A filter that is not saved yet and whose slug is still the one derived from its name follows its name (`Filter` → `Order status` gives `order_status`).
- An explicit edit of **URL name** is committed on blur or Enter, slugified and made unique among the dashboard's other filters. When the slug changes, every `{{old}}` in the dashboard's cards' options (text and heading text, link URL and label, click-behaviour URL template) is rewritten to `{{new}}` in the draft; `{{old_2}}` is left alone. Links already shared that carry `?old=` stop setting the filter; the help text under the field says so. Report renders read defaults by the current slug and are unaffected.

## Decisions

- KI-168: the plan says "clipped to their box". A chart is clipped to its box; a table's box grows with the table instead of clipping it, because a PDF page cannot scroll and clipping would drop rows with no sign. The table itself still caps its height (`max-h-[60vh]`) and prints its "Showing N rows" footer.
- KI-075: the confirmation is a plain yes/no (no typed word): the three actions can all be undone (restore from Trash, the dashboards survive the folder, a revert is itself a revision).
- No migration, no API change.
