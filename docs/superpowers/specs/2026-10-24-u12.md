# U12: print page width, dataset names and Connections wording

Package U12 of the Known-issues fix programme: KI-283, KI-301, KI-302.

## KI-283: charts shrunk in a PDF report

Premise (reproduces): a PDF report of a three-card dashboard on the demo stack came out on one
Letter sheet (612 x 792 pt) with the page laid out about 1120 CSS px wide and shrunk by Chromium to
fit the 816 px sheet (factor about 0.73), so a 12 px axis label printed at about 6.5 pt. The bar
chart's canvas also ran past its card's right border, because it was sized at the screen width.

Fix, in the renderer only (`renderer/server.js`): a PDF is printed on A4 and the print page is
opened in a window as wide as that sheet (794 px; Chromium's A4 is 794.56 px), so the layout is
printed 1:1. The single-object PDF gets 10 mm top and bottom margins (the print page has its own
side padding). Each object of a multi-object PDF is captured as a PNG at the same width before it is
placed on its sheet; a tall object is still scaled down to one sheet, as before. A PNG keeps the
requested size.

Decisions:

- A4, not Letter: the paper size most recipients print on outside North America. Letter was only
  Chromium's default, never chosen.
- A PDF ignores the schedule's custom width and height: they are an image's size, and a PDF is a
  sheet. The editor's help text says so.
- The renderer image must be rebuilt for the stack to show this; the print page itself is
  unchanged apart from a comment.

## KI-301: report cards ignore dataset display names and formats

Premise (reproduces): the same PDF shows `revenue`, `order_count` and `orderpriority`, where the
dashboard shows **Revenue** and **Orders** (the dataset's display names) since #751.

Fix: the print page has no session, so it cannot load the dataset as the dashboard does. The render
payload (`GET /api/render/payload`) now carries each card's `dataset`: its columns' and metrics'
display name, format and semantic type, nothing about its source. The print page layers them under
the chart's own settings with the same functions the dashboard uses (`datasetColumnDefaults`, and a
new shared `paramsWithDatasetDefaults` that the dashboard card now calls too), so a chart's own
column title still wins.

Decision: the payload does not check `dataset:read` for the report's owner. The report already runs
the dataset's queries as that owner and shows the rows; the display names say no more than that. A
dataset outside the grant's workspace yields an empty `dataset`.

## KI-302: the no-connection warning in the alert editor

Premise (reproduces, from code and a component test): the Condition tab says *This workspace has no
database connection yet. Add one under Workspace settings → Engines…*; the menu entry is
**Connections** (D5, KI-007).

Fix: *This workspace has no connection yet. Add one under Workspace settings → Connections before
creating an alert.* The same sweep changes two Data API texts on the workspace level that still said
database for the connection picked above them (the Preview note and the governed-connection
refusal). Texts about data "in the database" in general and Control Plane texts are unchanged.
