## What changes

- **Sign-in limit (KI-144, KI-002).** `RateLimiter` gains a failure-counting pair: `retry_after` (read only) and `record_failure`; `clear` forgets a key. Local login counts failed attempts only, a success clears them, five failures lock the next attempts for the lockout. The 429 carries `Retry-After` and `{ error, code: "rate_limited", retry_after_secs }`; the login page says "Try again in N minutes". The machine-IdP token endpoint keeps `check` (every attempt counts there).
- **Login response (KI-145).** The handler validates the new session and returns the same principal `/me` returns.
- **Scopes (KI-142).** The authorize request skips a configured `openid`; the client library always sends it.
- **SSO pre-registration (KI-185, decision D: by email).** Migration 0206 adds `workspace_invites` (workspace, email, workspace role, inviter). With SSO on, `POST /ws/{ws}/members` with an email nobody has signed in with stores an invite and answers `{ ok, invited: true }`; `GET`/`DELETE /ws/{ws}/invites[/{id}]` list and withdraw. The OIDC callback redeems the invites for the user's email through a port (`PendingMembershipRedeemer`, implemented by `MemberRepo`, so the membership recompiles engine policies like any other), only when the IdP sent `email_verified: true`. The role is pinned to workspace scope by a foreign key to `roles (id, scope)` with `role_scope = 'workspace'`, so an invite cannot grant a platform role. A redeem failure is logged and does not refuse the sign-in. The no-workspace landing names the user's email and has Check again and Sign out.
- **Roles (KI-019, KI-127).** The member and access-request role pickers read `GET /ws/{ws}/roles` (no `data_api_invoker`, works for a workspace admin). That catalog now returns `inherited_permissions` (parent chain, minus own); the page counts own + inherited and lists the inherited part under its parent. The page says why `data_api_invoker` is not listed.
- **Audit (KI-017, KI-018).** `GET /control-plane/audit` takes `hide_allowed=true` (drops `kind = decision AND decision = allow`) and returns `actorEmail`. The audit log opens on "Changes and denials"; *Recent changes* and the log name the actor by email.
- **Disable (KI-209).** The user page asks before disabling (it signs the user out). Enable acts at once.

## Not changed

- The bulk Disable on the Users list keeps its Undo toast.
- `POST /ws/{ws}/members` still accepts `data_api_invoker` from a direct API call; only the pickers stopped offering it.
