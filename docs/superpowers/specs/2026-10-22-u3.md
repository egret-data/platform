## What each row does

- **One refusal, inside the shell (KI-230, KI-231).** `Forbidden` (`routes/Forbidden.tsx`) is the one "no access" state. It has two levels: `page`, which gives the page its `h1`, and `section`, which gives a Workspace settings section an `h2`. It always offers *Go back* when there is history, and a link to a workspace the reader belongs to. It is built on a new shared frame, `StatePage`, which the 404, the placeholder and the "moved into Catalogs" pages also use (U1 left these pages to U3).
  - The area guards render the refusal inside `AppShell`. These are a non-member workspace, Control Plane and Governance.
  - A list page whose own read the server refuses renders the refusal instead of the red box: Endpoints, Clients, Activity, Flows, Executions, Namespaces and Triggers.
  - The settings sections (Members, Roles, Access requests, Shared objects, Engines) use the `section` level.
- **Hide what the reader cannot open (KI-231).** The client had no view of workspace permissions, so `GET /api/me/workspaces` now returns `permissions`: the caller's permissions in each workspace, from a fixed list of the page-gating ones (`PAGE_PERMISSIONS`: `data_api_endpoint:read`, `service_account:read`, `workflow:read`, `workspace:manage_members`). Each is decided by the same PDP call the routes make.
  - The sidebar leaves out the Data API and Workflows items the reader cannot open. Workspace settings leaves out the sections that need `workspace:manage_members`.
  - `/settings` opens the first section the reader may open. General has no gate.
  - The read is optimistic: while loading, or from a server without the field, every entry shows. The server stays the gate.
- **Governance sidebar (KI-225).** One group, *Governance*, with the six items. Sidebar headings truncate instead of wrapping.
- **Workspace settings (KI-005).** The settings nav's own Collapse is removed. The app sidebar's Collapse is the only one on the page.
- **KI-227.** The RisingWave tab is removed, because nothing behind it works. Egret provisions only Trino and StarRocks. A type other than those gets a tab only when the registry holds an engine of that type, so no engine loses its list. The "later phase" sentence is gone. On Access & governance, the cards are as tall as their content, and *How access works* sits under *Needs attention* in the left column.
- **Small screens (KI-233, KI-234).**
  - Below 1024px the app sidebar is the icon rail. Its toggle is hidden there, because it could change nothing.
  - `ui/table` scrolls sideways inside its container, with a shade on the clipped edge (`ScrollCue`).
  - Pill tab strips wrap. The Workspace settings strip scrolls with the same shade (`ScrollStrip`).
  - The narrow header no longer splits its free room between the workspace picker and a spacer.

## Decisions

- KI-227: removal, not a "not available yet" mark, as the plan prefers when nothing behind the tab works.
- The Data Lineage placeholder stays in the sidebar. Its row is KI-015, not in this package. It now says plainly, in the shared frame, that nothing on the page works yet.
- The refusal keeps the eyebrow *403 — Forbidden* (the code a reader quotes to an admin) and the heading *You don't have access to this page.*

## Rulebook

FE-STATE-5 (the shared state frame and refusal) and FE-PAGE-10 (small screens) are added in both languages.
