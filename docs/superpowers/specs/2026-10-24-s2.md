# S2 — the schedule editor keeps the stored schedule when opened on the Schedule section

Out-of-plan defect found during U7 (KI fix programme). No KI row, no migration, frontend only.

## Defect

Opening an existing alert, report or Data API alert straight on `?section=schedule` (a deep link or
a reload) showed a blank Repeat (when the stored period is not `Daily`), a blank Timezone (when the
stored zone is not the browser's), blank hour/minute pickers, and a preview such as
`Runs 0 0 * * * in .` for a stored `0 8 * * *`. Save then sent the damaged cron and zone:

- stored zone differs from the browser's: the body carries `timezone: ""` and the server refuses it
  (400/422), so the save fails;
- stored zone equals the browser's: only the cron is damaged, the server accepts it, and
  `0 8 * * *` is silently rewritten to `0 0 * * *`.

Going General -> Schedule was fine.

## Root cause

`ScheduleEditor` renders its fields at create-form defaults (`Daily` at 09:00, the browser's zone)
and copies the loaded schedule into them in a `useEffect`, one render later. On a deep link the
Schedule section's Radix `Select`s are already mounted when that copy lands, before Radix has
registered the native `<option>`s of their items. Radix's hidden native `<select>`
(`SelectBubbleInput`) is pushed the new value, has no matching option, reads back `""`, and its
`change` handler calls `onValueChange("")` (confirmed with a stack trace through
`@radix-ui/react-select` `index.mjs:1122`). From General the Schedule section mounts after the copy,
so no select ever sees its value change.

## Fix

Do not render an existing schedule's form until the loaded values have been copied in
(`hydrated` flag set at the end of the hydration effect; the editor returns `null` until then). The
controls then mount holding the stored values, so no select sees the change, in any section. The
dirty-state baseline waits on the same flag, replacing the `name !== existing.name` heuristic.

Not chosen: ignoring `""` in each `onValueChange`. It hides the symptom per control and leaves every
other select in the form (database, operator, target, format) exposed to the same race.

## Tests

`ScheduleDetail.test.tsx` "Schedule section opened by a deep link (S2)": alert `0 * * * *`
(Hourly), report and Data API alert `0 8 * * *`, each in a non-default zone, deep-linked through the
real `ScheduleDetail` route; asserts Repeat, Timezone, the preview, and the cron and zone Save sends.

## Also

`toCron` returned `undefined` for a period outside its union (the `""` above, through the picker's
`v as ...` cast); on this code the hourly deep link then crashed the page in `humanizeCrontab`
(`reading 'trim'`). It now throws a named error from an exhaustive `default` instead, covered in
`cronSchedule.test.ts`.
