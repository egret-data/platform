# KI-316 concurrent warehouse create, KI-239 worker claim flake (P2-A4)

## KI-316
`create_lakekeeper_warehouse` reads the warehouses, compares storage
(`refuse_overlapping_storage`, #806) and then asks lakekeeper to insert. Two
creates at the same moment can both read before either inserts, so both pass.

Decision: one transaction-level advisory lock (`WAREHOUSE_CREATE_LOCK`) taken
on the write pool before the check and held until lakekeeper's create has
returned (commit visible). One global key: creating a warehouse is rare and
the overlap is decided over every warehouse. The normalisation is unchanged;
the out-of-scope residuals (two host names, AWS-by-region) stay open.

Red test: hold the lock as a create in flight would, start a create, assert
it waits, land an overlapping warehouse, release; the create must 409.

## KI-239
`a_discard_only_block_claim_survives_renewal_and_the_poll` was rewritten in
#730 (events, not sleeps). Premise re-verified by stress runs; see PR.
