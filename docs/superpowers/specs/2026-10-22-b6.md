# B6: Engines and monitor (KI-194 to KI-201, KI-213)

Package B6 of the known-issues fix programme (`docs/superpowers/plans/2026-10-21-known-issues-fix-programme.md`).
The Docker engine provisioner (`EGRET_ENGINES__PROVISIONER=docker`) runs Trino engines as containers on the demo stack.

## What each row does

| Row | Cause | Change |
|---|---|---|
| KI-194 | `/cluster` called `GET /v1/node`, which Trino 483 does not serve (it is bound only with Airlift discovery, 404 otherwise), so the whole summary was a 502. A JWT-delegation engine has no password authenticator, so `egret-monitor` could not sign in either. | Nodes: `/v1/node` when it answers, else `SELECT http_uri FROM system.runtime.nodes`; `nodes: null` (unknown, shown as `—`) when neither answers. Sign-in on a JWT-delegation engine: the viewer's own engine JWT (the minter SQL Lab uses), `Authorization: Bearer` + `X-Forwarded-Proto: https`. The engine's policy then decides which queries the viewer sees and may cancel. Impersonate and open engines are unchanged (`egret-monitor`). The catalog test (`SHOW SCHEMAS`) shares the same sign-in. |
| KI-195 | The UI did not know what runs an engine. | `EngineDto.runtime` (`kubernetes`/`docker`, provisioned engines only). On Docker the Logs and Exec buttons are hidden and a note says to use `docker logs`. |
| KI-196 | Copy written for Kubernetes. | Restart, Delete, Settings and Review changes say containers on Docker. |
| KI-197 | The wizard sends the flat default `workerReplicas: 2` beside the per-role block the engine is rendered from. | The server sets the flat `coordinatorReplicas`/`workerReplicas` from `trinoConfig.{coordinator,worker}.replicas` (1 when absent) on create and update. |
| KI-198 | The form always emitted `auth.passwordUsers: []`; the dialog had no save. | Empty `passwordUsers` is omitted, and a missing key equals an empty list in the diff. **Save changes** opens Review changes, which saves only on its own **Save changes**. |
| KI-199 | The UI rebuilt `{name}-coordinator.{ns}:8080`, a name nothing answers to. | `EngineDto.endpoint`: the `host:port` a workspace connection dials (`Engine::client_endpoint`, shared with the assignment code). |
| KI-200 | The form dropped an ingress without a host. | The host field says it is required; Save and Create wait for it. |
| KI-201 | The `egret-lineage` policy transform is served only to a plugin whose hostname is a pod of an eligible engine (`host_is_engine_pod`). A Docker container's hostname was its id, so no Docker engine ever got it. | Docker containers get pod-shaped hostnames: `{engine}-coordinator-docker-0`, `{engine}-worker-docker-{i}` (none past 63 characters). No policy content changes. |
| KI-213 | `demo-down` removes engine containers; Restart had nothing to restart. | Restart of a Trino engine that ran (row not `provisioning`) and now has no pod or container re-applies its stored spec, which creates them again. |

## Decisions

- KI-194: the monitor runs as the person viewing it, not as a new system principal with impersonate rights on every user. Platform admins hold all-access on their engine's profile, so they see every query; anyone else sees what the engine lets them see.
- KI-201, what is granted to whom: unchanged from view governance R5. Only the Ranger plugin of a Trino engine egret provisions in JWT mode, bound to the profile, is served the transform; it gives `egret-lineage` `use` and `select` on the catalogs that profile's engines attach, `impersonate` of itself, `execute` on query ids and `alter` of `query_max_run_time`, and denies everything else. Only egret mints a token for `egret-lineage`, and it sends only `EXPLAIN` as it.
- KI-213: Restart recreates rather than egret recreating at start-up: a start-up sweep would recreate engines an operator removed on purpose.
