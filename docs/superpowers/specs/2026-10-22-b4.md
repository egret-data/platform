# B4: Alerts and reports delivery

Package B4 of the known-issues fix programme (`docs/superpowers/plans/2026-10-21-known-issues-fix-programme.md`).
All seven rows reproduced on main (`c01639cab`) on the Docker demo stack before any change.

| Row | What changes |
|---|---|
| KI-032 | `AutomationRunner::run_now` writes the outcome onto the schedule (`last_state`, `last_value`, `last_eval_at`) through `scheduler::record_manual_outcome`. `next_run_at` stays as it was. A row a tick has claimed (`working`) is left alone, so a manual run cannot make it claimable mid-run. The frontend `runNow` mutation now invalidates the list and the detail as well as the run log. |
| KI-033 | A firing is `success` only when every destination took it; otherwise the run (and the schedule's last state) is `error`, so the list's *Failing* count and badge show it. The grace period starts from the last run that reached someone (`notification_sent_at IS NOT NULL`) instead of the last `success`. |
| KI-034 | Delivery tries every destination and keeps every failure, each prefixed with its destination (`email: …`, `webhook <host>: …`, `slack #channel: …`), joined with `; `. A webhook is named by host only: its path or query may hold its secret. |
| KI-157 | The default report subject drops the ` report` suffix when the name already ends in the word "report". |
| KI-167 | The renderer client sets a per-request timeout derived from the number of pages; a timeout is reported as one. Render tokens live as long as that budget. |
| KI-169 | `csv` and `text` reports format numbers like the chart table's default (at most three decimals, trailing zeros dropped); `text` also groups digits. |
| KI-173 | A tick runs its claimed schedules side by side, at most four at a time. |

## Decisions

- **Delivery failure and the grace period (KI-033).** All destinations failed: `error`, no grace, the next tick
  tries again (nobody was told, so there is nobody to spam). Some destinations failed: `error`, grace starts,
  because re-firing every tick would spam the recipients who did get the message. No new state and no migration:
  `error` with the per-destination detail is what the list already marks as failing. An attachment that was
  skipped (a note) is not a failure and keeps `success`.
- **Renderer timeout (KI-167): derived, not a config key.** `render_budget(n) = 30 s × (n + 1)`: 30 s per page
  covers the renderer's 20 s ready wait plus load and capture; the extra page covers waiting behind one other
  render for one of the renderer's two capture slots. The page count is known on every call; a key would have to
  be tuned to the largest report anyone writes.
- **Number format (KI-169).** Text follows the table exactly (`1,035,681,023.49`). CSV rounds the same way but
  does not group (`1035681023.49`): a grouped number is text to a spreadsheet in any locale whose decimal
  separator is not `.`. Integers keep every digit. A column's own format settings (decimals, currency, prefix)
  are not applied; only the table's defaults are mirrored.
- **Concurrency (KI-173): four.** The renderer captures two pages at a time and every alert is an engine query;
  four lets a quick alert finish beside a slow report without flooding either. A constant, like the existing
  batch size of 20.
