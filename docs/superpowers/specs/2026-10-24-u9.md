# U9: Workflows validation and display

Package U9 of the Known-issues fix programme (`docs/superpowers/plans/2026-10-21-known-issues-fix-programme.md`).

## Rows

| KI-119 (S2) | Reproduces: `DELETE` then `POST` of the same id is a 409 "a trashed flow still holds"; `GET /flows?trashed=true` ignores the flag; no restore or purge route. | `GET /flows?trashed=true` lists the trash (with `deleted_at`). `POST /flows/{id}/restore` brings a flow back (and re-syncs its triggers, so its schedules start at their next tick). `DELETE /flows/{id}/permanent` deletes a flow that is already in the trash; it frees `(namespace, flow_id)`; versions and trigger state go by `ON DELETE CASCADE`, executions stay with `flow_id = NULL`. ## Decisions

- KI-123: "Draft" is said in the version slot, not by replacing the *Active* chip (see the row).
- KI-119: purge is `DELETE …/permanent` and refuses a flow that is not in the trash (409), so it can never be the first step that removes a flow. Restore keeps `state` as it was.
- KI-121/122 are warnings (the plan's choice): a saved draft that the engine reads differently from what it says is now told, not refused.
