## 1. Problem

egret renders Kestra's Pebble expressions with minijinja behind a rewriter (`EW src/runners/rewrite.rs`) and a comparison pass (`EW src/runners/cmp_rewrite.rs`, `compare.rs`). Where the two engines differ, a stored flow gets a different answer in egret: an expression Kestra refuses renders (so a run Kestra FAILED succeeds and runs more tasks), or an expression Kestra answers is refused. Row #5 lists the known differences. The survey measured every item on both engines with the same 99 probes and found that the row is partly wrong (§2.2), too narrow (integer arithmetic, operators, `and`/`or`) and holds one item that is not renderer work (`subflow()`).

Banks (upper bounds from cause attribution; the executor suite was not run by the survey): executor oracle about 11 strict, 15 at most; expression oracle 22 of the 129 baselined entries at most.

## 2. Decisions

### 2.1 User decisions, 2026-10-28 (asked, answered)

- **Q1. `subflow()` leaves #5.** It moves to row #12 "Subflow in full", after #6 (flow-level `outputs:`). It starts a whole child execution synchronously inside a render and banks 0 (survey §1.7). In #5 only its refusal's owner changes, from "W6" to "#12".
- **Q2. Kestra's integer arithmetic is adopted.** `7 / 2` is `3`, `long` overflow wraps as Java's does, and an integer or decimal `/ 0` fails. A release note states the changed behaviour of stored flows (D2, plan A8).
- **Q3. The adjacent items are in scope.** The items the row does not name are fixed too: the `equals` and `contains` operators (and `..`, measured with them), strict boolean `and`/`or`, the tests `even`/`odd`/`iterable`, the `escape` strategy `json`, `null < 1` answering `false`, integer division, and long overflow.
- **Q4. `render()` on run-time data is allowed**, with a nesting cap of 16 and `secret()` still confined. D9 states what confinement means in code.
- **Q5. W9c's ruling is reversed:** a `BigDecimal` is computed as Kestra computes it, not refused (W9c spec §15 and the W9c plan's amendment of 2026-10-07 are superseded for arithmetic).
- **Q6. The "deliberate" `coalesce-nested-absent` baseline is reversed:** `??` answers through a missing member or index chain, and the entry is re-banked (`oracle/baseline.txt:79-80` loses it).

### 2.2 Corrections to the roadmap's premises

Measured in the survey (§7) and binding on this design:

1. **There is no chained comparison in Kestra.** Pebble parses `a < b < c` left-associatively, so the outer comparison sees a Boolean and throws; `1 == 1 == true` is `true`. The row's "lazy chained comparisons" is therefore not a laziness fix: a chain compiles left-associatively (D1). The laziness that diverges is `??`'s right operand (D6).
2. **`??` on a missing root already works** (`coalesce-absent` passes). The gap is a member or index chain through a missing value (`trigger.body ?? 'h'`, `obj.a.b ?? 'h'`) and the eager right operand.
3. **`errorLogs()` does not need a task-log store.** egret has one since W11 (`EW src/logs/`). It needs a query (this execution, level ERROR) and a load **before** the render, because minijinja functions are synchronous (D11).
4. **`taskrun.value` is a one-line render-context fix** at `EW src/worker/render.rs:866`, which writes `"value": r.value` even when it is null; Kestra omits the key (`KR RunVariables.java:162-164`). The renderer already agrees with Pebble (D7).
5. `escape` has five strategies in Pebble 4.1.2, not four: `json` too (D12).
6. The bank estimate "~8–10" is about 11 strict and 15 at most (§4).
7. The cause table's "Loop unattributed (4)" is probably partly renderer: `loop-object` and `loop-object-in-list` use `is json`, and `if-in-flowable` uses `equals`. Unproven until B2 and A6 measure it.
8. **Survey correction (this design, from `javap -c` of `io.pebbletemplates.pebble.utils.OperatorUtils` in `pebble-4.1.2.jar`):** the survey's row "`fromIon(ion='1') / 3` is `0` because `BigDecimal.divide` keeps the dividend's scale" is mis-explained. Ion `1` is an integer, so this is Long division. Pebble's `BigDecimal` division uses `MathContext.DECIMAL128` (D3).
9. **Measured by A1, 2026-10-28: a `BigInteger` operand goes through `longValue()`, not `intValue()`.** D2's reading ("through `intValue()`, which truncates") is wrong. `{{ b + 1 }}` with `b = 99999999999999999999` is `7766279631452241920` (the value mod 2⁶⁴, plus one) and `{{ b * 2 }}` is `-2914184810805067778`; `b + 0.5` is the Double `1.0E20`. A3 follows the measurement (golden entries `arith-operand-biginteger-*`).
10. **Measured by A1, 2026-10-28: `op-contains-boxed-int` cannot bank in A6.** Its golden is `false` because of the Integer/Long distinction D2 records (`oracle/README.md` "`contains` does not work on a number that came from the context": a context `[1, 2]` holds `Integer`s, the literal `2` is a `Long`, `Integer.equals(Long)` is `false`; A1's `operator-contains-boxed-int-context`, with both sides from the context, is `true`). egret's values carry no Integer/Long distinction, so a faithful `kestra_contains` answers `true` there. Unless A6 finds a way, the entry stays baselined, re-attributed to D2's divergence, and the #5a totals in §4 and plan A6/A8 move by one: 13 old entries un-baselined, not 14 (129 → 116, not 115).
11. **Measured by A1, 2026-10-28: what `kestra_bool` (D5) must do.** Pebble coerces each `and`/`or` operand: a number is true when non-zero (`0 and true` is `false`, `2 and true` is `true`, `0.0 or false` is `false`), a string when non-empty (`'' or false` is `false`, `'false' or false` is `true`), a list or a map fails with a `ClassCastException`, and a null fails with `null value used in and operator and strict variables is set to true`, under `or` too. The result is always a boolean.
12. **Measured by B1, 2026-10-29: `abbreviate(0)` does not fail.** D13's "`n <= 0` fails" is wrong at zero: `'abc' | abbreviate(0)` is `abc`, the input unchanged; only a negative width fails (`Invalid argument to abbreviate filter; must be greater than zero`). Golden entries `filter-abbreviate-zero`, `filter-abbreviate-negative`. B4 follows the measurement.
13. **Measured by B1, 2026-10-29: the survey's `escape` `json` row is wrong.** Survey §1.11 shows `é` unescaped (`a\"b\\c\n/é\u0001`); Kestra writes `\u00E9`. unbescape's `JsonEscape.escapeJson` (level 2) escapes every non-ASCII character as `\uHHHH`, and `&` as `\u0026`. Golden `filter-escape-json-survey` and the `filter-escape-json-boundary-*` batch hold the measured values; B5 follows them, not the survey table.
14. **Measured by B1, 2026-10-29: what D8 and D10 leave open.** `is json` is `true` for `''` and for `'1 x'` (Jackson reads the first value and stops), and fails on a list, a number (`ClassCastException`) and a null (`argument "content" is null`), not only on a map. `is empty` uses `trim()`: a no-break space (U+00A0) is not empty. `max`/`min` keep the **first** operand on a tie (`max(2.0, 2)` is `2.0`, `max(2, 2.0)` is `2`), `max()` renders empty, and the `<x>` in D10's `invalid operands for mathematical comparison [<x>]` is the operator (`GREATER_THAN`, `LESS_THAN` under `min`), not the operand. `merge` of a map with a list adds each element as a key mapped to itself (`{"a":1,"1":1}`), and a null argument answers the input.
15. **Measured by B2, 2026-10-29: `null` is registered as `null`, not as `none`.** D8's "the test is registered as `none`" would over-accept: Kestra refuses `{{ x is none }}`, `{{ x is NONE }}` and `{{ x is NULL }}` (`Test [none] does not exist.`); the null literal's four spellings are a literal's, and a test name is a bare identifier. B2 keeps the rewriter from translating a word after `is`/`is not` (`rewrite::follows_a_test_operator`) and binds `null` under its own name; `none` stays removed. Also measured: every engine test ignores its arguments (`'a' is json(1)` is `false`), and `is json` is Jackson's `readTree` on the first value only (a root number must end at whitespace, depth and integer length are capped at 1 000; oracle README "What package #5b's Task B2 measured"). Executor: B2 banked `valids/loop-object` and `valids/loop-object-in-list` (`item.value is json`), which the plan did not predict, beside the expected `valids/task-runif-taskswithstate`.
16. **Read by B4 from the bytecode, 2026-10-29: item 12's `abbreviate(0)` is the input only for a short string.** `AbbreviateFilter` returns the input when it is shorter than the width or three UTF-16 units or fewer, and cuts plainly when the width is three or less, so `'abc' | abbreviate(0)` is `abc` (the golden) while `'abcdef' | abbreviate(0)` is empty; only a negative width fails. Also from the jar: `merge` of a list with a map appends one single-entry map per entry (`addAll(map.entrySet())`), and `rsort` casts to `List`, so `split`'s array is refused where `sort` sorts it. B4 ports these; `runners::filters::tests::pebble_core_filters_follow_the_jar` pins them.

### 2.3 Design decisions

Controller decisions under the autonomy rules, recorded here. Each D names the survey section it comes from.

- **D1. Strict relational comparison (survey §1.3, §1.12).** `CmpOp::apply` (`EW src/runners/compare.rs:357-379`) stops falling back to minijinja's total order (`values_cmp`). Numbers compare numerically (Long, Double and BigDecimal widened as D2 widens them), strings with Java's `compareTo`, and any other pair fails with Kestra's message (`Could not perform … comparison`, the text measured in A1). A null operand on either side answers `false` for `<`, `<=`, `>`, `>=`. `==`/`!=` keep their present `OperatorUtils.equals` semantics. A chain is compiled **left-associatively**: `a < b < c` becomes `kestra_lt(kestra_lt(a, b), c)`, which fails by the rule above; `kestra_compare_chain` (`compare.rs:445`) is removed with its eager-evaluation test (`compare.rs:825`). The pinned tripwire `the_one_corpus_comparison_pebble_refuses_and_minijinja_answers` (`EW src/executor/mod.rs:9708`) flips to assert the failure.
- **D2. One arithmetic seam, ported from `OperatorUtils` (survey §1.1, Q2).** A third compile pass in the `cmp_rewrite` style turns binary `+ - * / %` into `kestra_add`, `kestra_sub`, `kestra_mul`, `kestra_div`, `kestra_mod`, keeping minijinja's precedence (as `cmp_rewrite` does for comparisons). Unary minus, `~` and every filter or function that does its own arithmetic (`range`, `loop.index`, date functions) are untouched. *(Unary minus: superseded by A8, which compiles `-x` to `kestra_mul(-1, x)`; see §6.1.)* The functions port `OperatorUtils` as disassembled:
  - **`add`:** if either operand is a String, the result is `String.valueOf(left) + String.valueOf(right)` (egret's Java-style text of each value, the one `~` uses); if the left is a List, `addToList`; otherwise numeric. **`sub`:** a List on the left is `subtractFromList`; otherwise numeric. **`mul`, `div`, `mod`:** numeric only.
  - **numeric:** each operand goes through `toNumber`: a number stays itself; a String containing `.`, `e` or `E` parses as a double, any other String as a long (a bad string fails with `Cannot convert to Number: <x>`); anything else fails. Then the widening order is **BigDecimal, then Double, then Long**: if either is a BigDecimal, D3; else if either is a Double, Java `double` arithmetic (`1.0 / 0` is `Infinity`, as Kestra); else Java `long` arithmetic: wrapping `+ - *`, truncating `/` (`-7 / 2` is `-3`), `%` with Java's sign rule, and `/ 0` or `% 0` failing with Kestra's message (`Could not perform division`, exact text from A1).
  - **What A1 measures before A3 fixes the rules:** a null operand, a boolean operand, `'5' * 2`, `1 + 'a'`, `[1] + 2`, `[1] + [2]`, `[1, 2] - 1`, a map operand, and a `BigInteger` operand (`OperatorUtils` sends a `BigInteger` down the integer branch through `intValue()`, which truncates). The code follows the measurement where it differs from this reading.
  - **Recorded divergence, Integer vs Long.** Pebble has a fourth branch: two `java.lang.Integer` operands use 32-bit `int` arithmetic before widening the result to `long`. A template literal is a Long, but a context value Jackson read from JSON is an Integer when it fits 32 bits, so `{{ outputs.a.x * outputs.a.y }}` can wrap at 2³¹ in Kestra. egret's values carry no Integer/Long distinction and every integer is a Long here. A1 adds a probe over two context integers to measure it; if Kestra wraps, the entry is baselined as this divergence and the release note names it. Porting it would need the rewriter to tell a literal from a context value; not in #5.
- **D3. BigDecimal computed as Kestra does (survey §1.13, Q5).** If either operand is a BigDecimal (`filters::BigNumber` with `class_name` `java.math.BigDecimal`: a `kv()` decimal, `number(type='BIGDECIMAL')`, and every value Kestra types as `BigDecimal`, which A4 checks for `fromIon` decimals), **both** operands become `BigDecimal.valueOf(x.doubleValue())`, which is why Kestra loses precision on a 30-digit value (`…890.5 + 1` is `123456789012345680000000000001.0`). Then `add`/`subtract` are exact and `multiply`/`divide`/`remainder` use `MathContext.DECIMAL128` (34 digits, `HALF_EVEN`) with Java's preferred-scale rules, which decide the printed text (`1.50 * 2` is `3.00`). `/ 0` fails. `BigDecimal.valueOf(double)` is `new BigDecimal(Double.toString(d))`, so it reuses egret's existing Java `Double.toString` port. The implementation is a hand port on `num-bigint` (already in the lock); the `bigdecimal` crate (0.4.11, in the offline cache) is acceptable only if it reproduces every golden entry of A1's batch. The `BigNumber` refusal at `EW src/runners/filters.rs:2936` and its doc comments go; a `BigInteger` follows D2's measured branch.
- **D4. Behaviour change for stored flows (Q2, release note).** These answers change: integer `/` truncates; long overflow wraps; integer and decimal `/ 0` fail; a number-vs-string, boolean or list comparison fails; `null < 1` is `false`; a `<` chain fails; `and`/`or` return a boolean; arithmetic on a string operand follows D2; `{{ taskrun.value }}` fails where the task run has no value; arithmetic on a decimal `kv()` value computes. These become more lenient: `??` through a missing chain, the `equals`/`contains`/`..` operators. The note goes to the docs repo (plan A8) and to the PR description of #5a.
- **D5. `equals`, `contains`, `..` and strict `and`/`or` (survey §2, Q3).** The rewriter (`EW src/runners/rewrite.rs`, the operator tier at `:1096-1130`) compiles `a equals b` to `kestra_eq(a, b)` (Pebble's `equals` is `OperatorUtils.equals`, as `==`), `a contains b` to `kestra_contains(a, b)` (Pebble's `ContainsExpression`: map key, list element, string substring; A1 measures each and a boxed int), and `a..b` to `kestra_range(a, b)` (inclusive, Pebble's `RangeFunction`; A1 measures descending and character ranges). Each gets Pebble's precedence. `and`/`or` keep minijinja's short circuit (`false and missing.y` stays `false`, as Kestra) and wrap **each operand** in `kestra_bool(x)`, which passes a boolean and otherwise does what A1 measures Pebble doing (a cast failure or a coercion), so the result is a strict boolean. The `rewrite_shape_only` test helper (`rewrite.rs:1671-1690`), which exists because these words did not parse, is removed with its tests rewritten to parse.
- **D6. `??` and `???` through a missing chain, with a lazy right side (survey §1.4, Q6).** When the left operand of `??` or `???` is a **path** (a root name followed by `.name`, `['literal']` or `[integer]` steps), the rewriter compiles it to `kestra_path(root, 'a', 'b', 0)`, where a missing root reaches the function as `Undefined` (as today) and a missing step answers `Undefined` instead of raising. The whole operator becomes `(P) if kestra_present(P) else (R)` for `??` (present = defined and not null) and `kestra_defined(P)` for `???`, so `R` is evaluated only when needed (`x ?? missing.y` is `1`). `P` is evaluated twice; a path read is pure, so this is safe. When the left operand is **not** a path (a call, a filter, an arithmetic expression), it keeps today's form (`kestra_null_coalesce(L, R)`, both eager), recorded as a divergence with one golden entry (`f() ?? missing.y`). An implementer who finds a single-evaluation form that the parser gate accepts may use it for every left operand. Strictness everywhere outside a `??`/`???` left operand is unchanged.
- **D7. The render context (survey §1.2, §1.14).** `EW src/worker/render.rs` omits `taskrun.value` when the run has no value, and `taskrun.parentId` and `taskrun.iteration` when null, as `KR RunVariables.java:158-166` does. A7 checks that a `Loop`/`ForEach` iteration run carries `value` exactly when Kestra's does. `task.type` is set for every task kind: `PlanTask` carries the type string from the flow source. Kestra writes `task.getType()` (`KR RunVariables.java:124-129`); A7 reads whether that is the alias as written or the canonical class name and follows Kestra (default: as written).
- **D8. Tests (survey §1.10).** `null` (reached through the `none` spelling the rewriter produces; the test is registered as `none`), `empty` (`""`, whitespace-only strings, `[]`, `{}`, null are empty; `0` is not), `map`, and `json` (a string that parses as JSON; a map operand **fails** with Kestra's `ClassCastException` text, a recorded oddity kept for parity). `even`/`odd` fail on a String and `iterable` is `false` for a String, as Pebble. A missing root under `is null` fails (strict), as Kestra. The fence `the_defined_test_is_pebbles_and_it_is_the_only_one_overridden` (`EW src/runners/env.rs:2962`, `:3005`) is rewritten to list the tests egret overrides.
- **D9. `render()` and `renderOnce()` (survey §1.5, Q4).** Registered on the shared `environment()`. `render(toRender, recursive=true)`: a non-string is returned as it is; a string is rendered against the **caller's render context** (read through the `egret context scope` global, as `fetchContext()` reads it), through the same front end (`compile_source`: raw-region protection, rewrite, comparison and arithmetic passes), recursively to a fixpoint when `recursive` is true and in one pass when false. `renderOnce(x)` is `render(x, recursive=false)`. Nesting is counted as Kestra counts it (`KR pebble/functions/RenderFunction.java:46-54`): the top-level render is depth 0, each `render()` renders at depth + 1, and a call made at depth 16 fails, so 16 nested calls succeed and the 17th fails with Kestra's text `Maximum render() nesting depth (16) exceeded at line <n> — check for circular render() calls in your template.` A `recursive` that is not a boolean fails with `The 'render' function expects an optional argument 'recursive' with type boolean.` Each nested render has its own fuel and the 1 MiB output cap (`env::MAX_OUTPUT_BYTES`), so a top-level render does at most 17 × `FUEL` of work. **What "`secret()` stays confined" means, in code:**
  1. The nested render always runs on a **fresh `environment()`**, never on the caller's environment. It does not inherit the `extend` closure that `render_once_with` applies (`EW src/runners/env.rs:2179`), so inside `render_with_secrets` (`EW src/runners/secrets.rs:141`) pass 3, the text a `render()` evaluates sees the **refusing** `secret` (`functions::SECRET_REFUSAL`), and `{{ render(inputs.x) }}` with `inputs.x = "{{ secret('db') }}"` fails with that refusal on every task kind, plugin tasks and the three http tasks included.
  2. No secret name is collected from run-time text: `literal_keys` scans the author's source only, and the collecting render (pass 1) reaches the nested render with the refusing `secret` too, so a key reachable only through `render()` is never fetched and never handed out.
  3. `text_uses_secret` (the publish gate and the per-string resolver switch) is unchanged. Its doc comment, which says `render()`/`renderOnce()` are refused and "if either arrives, this must change with it", is rewritten to state rules 1 and 2 instead. A test pins rule 1 in the shared path and in `render_with_secrets`.
  4. **Forbidden roots carry into the nested render.** `render_str_guarded`'s forbidden list (`["trigger"]` for a webhook's `inputs:`) is checked on the nested text before it renders, so `render(vars.tpl)` with `vars.tpl = "{{ trigger }}"` is refused as the outer text would be. Without this, `render()` would launder a forbidden root past the per-pass check.
  5. `http()` stays `Unsupported`. What `render()` exposes to whoever starts an execution is what the author's own text already reaches: the render context and `kv()`, `read()`, the namespace-file functions and `fetchContext()` within the execution's own workspace. This is Kestra's reach (accepted, Q4).
  - Observation recorded for the reader: egret's non-plugin renders already run a fixpoint loop (`Passes::Fixpoint`, up to `MAX_RENDERING_AMOUNT`), which evaluates text a pass produced; `render()` adds that reach to plugin-task properties, which render once. Rules 1–4 are what keep that from reaching a secret or a forbidden root.
  - The standalone expression oracle cannot carry `render`/`renderOnce` (`oracle/name-surface.txt`), so evidence is unit tests and the executor corpus: `valids/variables` banks; `valids/replay-revision` must still FAIL (guard).
- **D10. `max`/`min` (survey §1.8).** Variadic; one argument is returned as it is; null arguments are skipped (`min(null, 1)` is `1`); numbers compare as D1 compares them and the larger (smaller) operand is returned with its own type (`max(1, 2.5)` is `2.5`); a non-number fails with `invalid operands for mathematical comparison [<x>]`.
- **D11. `errorLogs()` (survey §1.6).** Worker task renders only, as in Kestra; anywhere else (executor-side renders, triggers, inputs) it fails with Kestra's text `The 'errorLogs' function can only be used in the Worker as it access logs from the database.` (`KR pebble/functions/ErrorLogsFunction.java:45`). The worker loads the list **before** the render, as the kv and namespace-file prefetch does (`tests/prefetch_hold.rs` pattern), and only for a string the renderer's own front end says calls `errorLogs` (`env::name_in_code`). The list is this execution's ERROR lines, each in Kestra's `LogEntry` shape (`taskId`, `taskRunId`, `message`, `level`, `timestamp` and the other non-null fields Kestra writes; B7 reads the shape), oldest first. **Divergence:** Kestra polls while the list is empty, from 100 ms up to 1 s apart, for at most 5 s (`:51-62`); egret waits at most 1 s (B7 measures whether the log writer's batching leaves the first read empty, and may flush the writer before the read instead). A log message is data: it is never rendered again.
- **D12. `escape` strategies (survey §1.11).** `html` (unchanged), `js`, `css`, `url_param` and `json`, each ported from `unbescape` 1.1.6's level-2 rules exactly (the survey's probe table is the minimum golden batch). An unknown strategy fails with Kestra's `Unknown escaping strategy [x]`.
- **D13. The ten filters (survey §1.9).** `abbreviate` (`n <= 0` fails), `base64encode`/`base64decode` (UTF-8; Kestra's error text on a bad input), `merge` (list+list concatenates, map+map right wins, list+map appends the map), `nl2br` (no escaping), `numberformat` (`java.text.DecimalFormat` patterns), `raw` (identity; Kestra runs with `autoEscaping(false)`), `rsort`, `sha256` (hex, beside the existing `sha1`/`sha512`/`md5`), `urlencode` (`URLEncoder`, form encoding). **Divergence:** `numberformat` uses a pinned `en` locale, as egret's `date` filter does when no locale is given; Kestra uses the JVM default locale.
- **D14. Recorded, not changed.** A string literal that spans a newline is legal in Pebble and refused by the rewriter (survey §6 B6). `working-directory-taskrun-nested`, `working-directory-invalid-runif` and `envs`/`globals` are not renderer work (survey §2).

## 3. Shape of the change

- **#5a** touches `rewrite.rs` (D5, D6), `cmp_rewrite.rs` and `compare.rs` (D1), a new arithmetic module beside `compare.rs` registered by `env::environment()` (D2, D3), `filters.rs` (the `BigNumber` refusal), `worker/render.rs` and `executor/plan.rs` (D7). Every path that hands a template to the parser already goes through `env::compile_source` (`env.rs:1925`), so the new pass is added there and every probe (`referenced_roots`, `name_in_code`, `text_uses_secret`) sees what a render runs.
- **#5b** touches `env.rs` (tests, D8), `functions.rs` (`max`/`min`, `render`/`renderOnce`, `errorLogs`; the `REFUSED` table goes from 6 rows to 3: `secret`, `http`, `subflow` with owner #12), `filters.rs` (D12, D13), `secrets.rs` (doc comment, D9 rule 3), the worker's prefetch and `logs/repo.rs` (D11).
- #5b depends on #5a only through D10 (`max`/`min` use D1's comparison) and D9 (`render()` uses the front end with D2's pass).

**Now accepted (more lenient).**

- `??` and `???` read through a missing member or index chain: `{{ trigger.body ?? 'hello' }}` and `{{ obj.a.b ?? 'x' }}` answer the fallback instead of failing, and the right side is only evaluated when needed (`{{ x ?? missing.y }}` is `x`).
- The Pebble operators `equals` (`{{ a equals 'b' }}`), `contains` (`{{ list contains 'x' }}`, map keys, substrings) and `..` (`{{ 1 .. 3 }}` is `[1,2,3]`) now work; before, a template using them failed to parse.
- `??` and the ternary `? :` inside a named argument (`{{ fromIon(ion=x ?? '1') }}`, `{{ range(start=0, end=n ?? 3) }}`) now work; before, they failed with `non-keyword arg after keyword arg` or a syntax error.

**Known differences from Kestra.**

- **32-bit integers.** Kestra multiplies two integers that came from flow data (for example `{{ outputs.a.x * outputs.a.y }}`) in 32 bits, so `65536 * 65536` is `0` there; egret computes in 64 bits (`4294967296`). The same cause makes `{{ [1, 2] contains 2 }}` with the list from flow data `false` in Kestra and `true` in egret, and `{{ -n }}` for an integer past 64 bits differ.
- **`??` after a function call or filter** evaluates its right side even when the left side has a value: `{{ fromJson('1') ?? missing.y }}` fails in egret and is `1` in Kestra. With a variable path on the left (the common case) the two agree.
- **`contains` evaluates its right side** even when the left side is null: `{{ n contains (1 / 0) }}` with a null `n` fails in egret and is `false` in Kestra (a missing variable on the right is not an error in either).
- **`~` writes a boolean as `True`/`False`** (`{{ (true and 'x') ~ '|' }}` is `True|`; Kestra `true|`). `{{ true }}` alone prints `true`.
- **Precedence.** `not a == b` is `not (a == b)` in egret and `(not a) == b` in Kestra (the same for `not` before `contains`, `??` or `+`); `a * b ~ c` and a unary `-` or `not` before a filter group differently too. Parentheses make both engines agree.
- Comparisons between numbers are exact; Kestra compares through a double, so they can differ past about 16 significant digits.
- `{{ l.size ?? 0 }}`: Kestra reads Java methods such as `size` on a list; egret answers the fallback.
- `{{ taskrun.parentId }}` is `null` (Kestra: the id) when the parent task run was created in the same scheduling step as the child, the same gap `{{ taskrun.id }}` already has.
- Arithmetic chains of more than about 100 operators, and list operators past the limits above, fail in egret only.
