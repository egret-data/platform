# Workflow package #4 "HTTP and the unserved platform tasks"

**Status:** designed 2026-10-28; built 2026-10-28 on `feat/workflow-http` (Tasks C1–C7, PR in review). The as-built state and the known limitations are in §5. Roadmap row #4 of `docs/en/plans/2026-10-18-workflow-kestra-parity-roadmap.md`. Plan: `docs/en/plans/2026-10-28-workflow-http.md`. Survey (with file:line for every claim): `docs/en/specs/2026-10-28-workflow-http-survey.md`. Branch `feat/workflow-http`. Kestra is the checkout at `data-portal/kestra`, `96893b58`.

## 1. Problem

`io.kestra.plugin.core.http.Request`, `Download` and `SseRequest` do not exist in egret, and six egret-only task rows are registered with no handler, so a flow using any of them is refused as `task_type_not_served`. Request is the most used core task after Log. The oracle has no http flow, so this package banks **0** entries; evidence is new unit and integration tests.

## 2. Decisions

User decisions, 2026-10-28 (asked, answered): **Q1** egress option A; **Q2** `secret()` resolves on the three http tasks in this package (not #10); **Q3** wire `egret.sql`, remove three rows, defer two. The rest are controller decisions under the autonomy rules, recorded here.

- **D1. Egress (Q1).** Handlers run in the egret process, so they share its network position (Postgres, the Kubernetes API, engine admin endpoints, cloud metadata; the task-pod NetworkPolicy does not cover that pod). Policy **A**: parse the URL with `url::Url`, allow only `http`/`https`, resolve once, require **every** address to be public, pin the vetted addresses (`ClientBuilder::resolve`), disable automatic redirects and follow them by hand (at most 10), **re-vetting every `Location`**, call `.no_proxy()`. A per-deployment host allowlist `workflow.http.allow_hosts` (exact, case-insensitive host match, as `automation.webhook_allow_hosts` does) lets an operator open a private API. This is a recorded **security divergence** from Kestra, which has no default block (survey §1.2, §5).
- **D2. One guard.** `egret-automation/src/deliver/destination.rs` moves to a small shared crate/module that both `egret-automation` and `egret-workflow` use (a port rule forbids workflow depending on automation). Its range list gains NAT64 `64:ff9b::/96`, 6to4 `2002::/16`, Teredo `2001::/32`, v4-compatible `::a.b.c.d` and the whole `0.0.0.0/8`. The allowlist stays host-exact; a listed name is trusted whatever it resolves to (documented).
- **D3. Allowlist.** A **separate** key `workflow.http.allow_hosts` (a different blast radius from alert webhooks). Env `EGRET_WORKFLOW__HTTP__ALLOW_HOSTS`. No per-workspace list now (follow-up, needs a never-allow set).
- **D4. Flow-controlled transport.** `options.proxy` is **refused** (a flow-chosen proxy defeats pinning); `options.ssl.insecureTrustAllCertificates: true` is **refused** (Kestra's `!= null` bug is not copied); `options.auth.type: DIGEST` is **refused** (reqwest has none); `encryptBody: true` is **refused**; a `uri` with userinfo (`user:password@host`) is **refused** (controller decision, Task C3), so credentials never reach the `uri` output. Each refusal is a publish-time finding and a run-time failure for stored flows, naming the reason. Any port is allowed. *Controller decision, Task C7 (2026-10-28): `encryptBody` is Request's only (see D10's C6 note). A stored `Download`/`SseRequest` with `encryptBody: true` that reached a run fails before the request is built with `encryptBody: not a property of <type> (Kestra declares it on io.kestra.plugin.core.http.Request only). Remove it`, not with Request's text about the `body` output; `encryptBody: false` there is dropped.*
- **D5. `secret()` (Q2).** Resolved on `Request`, `Download` and `SseRequest` through `render_with_secrets`, as the plugin path does; the `validate.rs` `secret_outside_plugin_task` exemption is extended to these three types; resolved values are masked in every log line and error. Credentials are never logged (`Authorization`, `Proxy-Authorization`, `Cookie`, `Set-Cookie`). On a cross-origin redirect the `Authorization` header is dropped.
- **D6. Request.** Properties and defaults as Kestra (`uri`, `method` default GET, `body`, `contentType`, `formData`, `headers`, `options.{timeout,auth BASIC|BEARER,followRedirects default true,allowFailed,allowedResponseCodes,logs}`). Outputs `uri` (the request URI), `code`, `headers`, `body` (string, never parsed as JSON). Body decoded as UTF-8 with Kestra's illegal-code-point error. The body cap is **1 MiB** (egret's render cap, `runners/env.rs:204`), not Kestra's 19 MiB, with Kestra's message adapted: it points at `Download`. The status rule is Kestra's (`HttpClient.isAllowedStatusCode`; controller decision, Task C3): a non-empty `allowedResponseCodes` replaces the rule (only the listed codes pass, also over `allowFailed`); else `allowFailed` passes every code; else **any code below 400 passes** (so an unfollowed 3xx succeeds). The `headers` output keeps every header as Kestra does, `Set-Cookie` included; headers are never logged except through `options.logs`, where credential headers are always `******`. A multipart body is capped by `workflow.storage.max_file_bytes` (1 MiB without `[storage]`). A failure message carries at most 4 KiB of the response body, masked.
- **D7. Download.** Streams to internal storage through `Outcome.files` (template: `egret.sql` STORE), under a **stable** per-run file name (`saveAs` honoured, `Content-Disposition` honoured, both sanitised to one path segment), so a re-claim overwrites its own object. Cap `workflow.http.max_download_bytes` (default 1 GiB; Kestra has none). `failOnEmptyResponse` default true; the `Content-Length` check is kept. Without `[storage]` it fails naming the missing config. Outputs `uri`, `code`, `length`, `headers`. Controller decisions, Task C4 (2026-10-28): the cap is the smallest of `workflow.http.max_download_bytes`, `workflow.storage.max_file_bytes` and `workflow.storage.max_task_bytes`, named in the message, checked on `Content-Length` before reading and on the bytes as they stream (a crossed cap fails the upload, so no truncated object is stored); the fallback name is `download` plus the URI's extension (Kestra: a random temp name with that extension); `saveAs` and the `Content-Disposition` name are cut to the last segment after `/` or `\`, spaces become `+`, and the characters Java's quoting `URI` constructor escapes (`"`, `<`, `>`, `[`, `]`, `^`, a backtick, `{`, `|`, `}`, `?`, `#` and control characters) are percent-encoded; a `saveAs` that cuts to empty, `.` or `..` fails; `filename*` is decoded as RFC 5987 (Kestra's substring drops a character at each end); a failed `Content-Length` or empty-body check deletes the stored object.
- **D8. SseRequest.** Kestra's parser semantics; JQ via `jaq` (not jackson-jq 1.6; differences listed in the plan's report when found). Divergences, recorded: a status of 400 or above **fails** (Kestra never checks), and a cap of `workflow.http.max_sse_events` (default 10 000) and the task `timeout:` stop a stream (Kestra has neither). Outputs `uri`, `events`, `size`, `result`. Controller decisions, Task C4 (2026-10-28): the status rule is Request's (D6), so `allowFailed`/`allowedResponseCodes` can pass a 4xx; at `max_sse_events` the stream is closed and the task **succeeds** with those events, logging a warning; two memory bounds are added, 16 MiB of stream and 1 MiB of output JSON (egret's render cap), each failing with its own message; null outputs are left out (Kestra's `NON_NULL` output map); an event whose data lines are all empty has `data` null (Kestra fails on `toObject(null)`); `retry` is a number of seconds; JQ keeps the last text, number (as Java's `toString`) or boolean result per event and treats null, an array or an object as missing, as Kestra's lambda does; a program `jaq` cannot parse (jackson-jq's `$.field` form among them) fails before the request, as Kestra's compile does; jaq runs through the `jq` filter's sandbox (its bounds and 1 s deadline per event).
- **D9. Registry.** The FQCN rows plus Kestra's aliases `io.kestra.plugin.fs.http.Request` and `...Download` (Kestra declares both). Tests that used `http.Request` as the example of an unregistered type move to another unregistered FQCN.
- **D10. The six unserved rows (Q3).** Wire **`egret.sql`**: build the query port before `handlers_for` (`main.rs:2289` vs `:2981`) and add the `RefKind::Database` ownership resolver, because publish refuses the type today (`refs.rs:95`). Accept the open `run_as` question as is (`created_by` is the principal; recorded). **Remove** `core.http`, `core.slack`, `egret.dataset.refresh`. **Defer** `egret.dataapi.call` and `egret.report.send` (they stay registered and refused as `task_type_not_served`; their schema texts are corrected). Removing a row changes only the error code for flows that could never run (`task_type_not_served` -> unknown type). Controller decisions, Task C5 (2026-10-28): the ownership port is a new leaf trait `egret_query_api::DatabaseOwnerPort` (`workspace_of(id) -> Option<workspace>`), implemented by `egret_query::DatabaseRepo` and held by `WorkflowRefs.databases`, the same shape as `DataApiEndpointPort`; `database:` resolves **by id only** (a UUID), like every other `RefKind`, because `WorkflowRefPort::workspace_of` carries no workspace to look a name up in and a start runs the draft source, not the rewritten snapshot, so a name would publish and then fail at the task; a name, a foreign id and an unknown id are all `NotFound`; `egret.sql` is registered by `runtime::handlers_for` on every deployment (with or without a container runner) over egret-bin's one `Arc<EngineState>`, now built before `handlers_for`, with `fetch: STORE` writing to the installed store; the unserved probe in the tests moved from `egret.sql` to `egret.report.send` (deferred, stays unserved). Controller decisions, Task C6 (2026-10-28): the three rows are gone from `TASK_TYPES`, the schema stubs and the tests; `TASK_TYPES` is 40 rows = 30 served on every deployment + 4 script types (with a runner) + 4 executor-level + the 2 deferred types, a partition a `runtime` unit test now holds so no comment restates it; a flow still naming a removed type gets ONE `unknown_task_type` error at the task's path with a hint (`registry::REMOVED_TYPES`: `core.http` -> use `http.Request`/`Download`/`SseRequest`, `core.slack` -> post to a Slack webhook with `http.Request`, `egret.dataset.refresh` -> none), because without it `core.http`/`core.slack` would fall to `unsupported_flow_task`, whose text calls them Kestra control-flow tasks; publish and every start still refuse such a flow and write no execution (pinned in `tests/not_served.rs`), and an execution already stored with one still fails at the worker with `NoHandler`, as before; the deferred types' schema texts now say publish and every start refuse them and that `endpoint`/`chart` are ids; and `encryptBody` is one finding per http task: on `Request` the D4 refusal only (`spec::keys` no longer also calls it `unknown_property`, so `encryptBody: false` publishes as D4 says), on `Download`/`SseRequest` `unknown_property` only (it is not their property, and the refusal's text is about Request's `body` output). `property-treatment.json` is unchanged: none of the three was a measured row.
- **D11. Config.** `WorkflowConfig` gains `http.{allow_hosts, max_download_bytes, max_sse_events, max_redirects (10), connect_timeout_secs}`; documented in the config reference and `.env.example`-style docs as the repo does for sibling keys. *Correction, 2026-10-28 (Task C2, applied in C7): the key is `connect_timeout_secs` (default 10), not `connect_timeout`, because every duration key beside it carries a `_secs`/`_s` suffix. The repo has no config reference table (survey §3.8) and the helm chart leaves workflow tuning knobs out, so the keys are documented in the `WorkflowHttpConfig` doc comments, a commented block in `.env.example` (Task C7) and the user-facing `egret-data/docs` notes. Boot validation refuses a zero `max_download_bytes`, `max_sse_events` or `connect_timeout_secs` and an `allow_hosts` entry that is not a bare host (a scheme, port, path, `@` or whitespace); `max_redirects: 0` is allowed and means any redirect fails.*
- **D12. Out of scope.** `http.Trigger` (#11), per-workspace allowlist, a deployment-level egress proxy, `DIGEST`/`encryptBody` (refused), `options.logs` beyond redacted request/response lines.

## 5. As built (2026-10-28, Task C7)

Built on `feat/workflow-http`, Tasks C1–C6 (reports in the scratch `.superpowers/sdd/2026-10-28-workflow-http/`, not in git). Oracle unchanged, as §3 expected: ratchet **301 / 50 / 50 / 0**, `LIVE` 295, `VALIDATE_REFUSED` 25, `UNKNOWN_TYPE_REFUSED` 21. Evidence is the new unit tests and `tests/http_request.rs`, `tests/http_download.rs`, `tests/sql_served.rs`, `tests/not_served.rs`.

**Shape.** One egress guard in a new crate `egret-egress` (`vet`, `SsrfPolicy`, `Resolver`, the pinned client, manual redirects, `.no_proxy()`), used by `egret-automation` webhooks and by the three http tasks. `egret_workflow::http` holds the shared request model, refusals, status rule, masking and SSE parser; the handlers are `worker/handlers/http.rs` and `http/{download,sse}.rs`, registered by `runtime::handlers_for` on every deployment. `egret.sql` is served on every deployment (D10). `TASK_TYPES` is 40 rows: 30 served everywhere, 4 script types (with a runner), 4 executor-level, 2 deferred (`egret.dataapi.call`, `egret.report.send`).

**Config** (`[workflow.http]`, env `EGRET_WORKFLOW__HTTP__*`):

| key | default | meaning |
|---|---|---|
| `allow_hosts` | `[]` | hosts an http task may reach although they resolve to a private address; exact, case-insensitive, no port or scheme; a listed name is trusted whatever it resolves to |
| `max_download_bytes` | 1 GiB | `Download` cap; the effective cap is the smallest of this, `workflow.storage.max_file_bytes` and `workflow.storage.max_task_bytes` |
| `max_sse_events` | 10 000 | `SseRequest` stops reading here and succeeds with the events read, logging a warning |
| `max_redirects` | 10 | redirect hops followed, each re-vetted; `0` means any redirect fails |
| `connect_timeout_secs` | 10 | connect timeout when the task sets no `options.timeout.connectTimeout` |

**Bounds that are not config keys.** `Request` stores at most 1 MiB of body (egret's render cap; the message points at `Download`). `SseRequest` reads at most 16 MiB of stream and writes at most 1 MiB of output JSON; each fails with its own message. A failure message quotes at most 4 KiB of the response body, masked. A multipart body is capped by `workflow.storage.max_file_bytes` (1 MiB without `[storage]`).

**Redirects and credentials.** Redirects are followed by hand (when `options.followRedirects` is true, the default), at most `max_redirects` hops, and every `Location` is vetted again as a new destination, scheme included. On a hop that changes scheme, host or port, `Authorization`, `Proxy-Authorization` and `Cookie` are removed and stay removed for the rest of the chain. Method rules follow the Fetch standard, as Kestra's Apache client does: 303 turns any method but HEAD into GET, 301/302 turn POST into GET, 307/308 keep the method and body. A refused hop fails the task naming `workflow.http.allow_hosts`; the refused host receives nothing.

**Known limitations, recorded:**
1. **`egret.sql` `database:` takes a connection UUID only.** A name is refused at publish (`NotFound`), because `WorkflowRefPort::workspace_of` carries no workspace to look a name up in, and a start runs the draft source, not the publish-rewritten snapshot. Follow-up.
2. **`run_as`.** `egret.sql` runs as `flows.created_by`; an ad-hoc run with no flow and a flow whose creator was deleted are refused (D10, accepted). A `run_as` column is a follow-up (§4).
3. **The editor schema still offers refused options.** `HttpConfiguration` (`options`) is not a measured row, so the served Kestra schema still lists `options.proxy`, `options.ssl` and `DIGEST` in the auth union, although publish refuses them (`http_option_refused`). Follow-up: make it a nested row or filter it.
4. **Whole-map templates fail at run.** `headers`, `formData` and `params` must be maps; a single template string for the whole map (Kestra's `Property<Map>` accepts one) fails at run with `invalid http task`, and publish reports no D4 finding for such a task.
5. **JQ is `jaq`, not jackson-jq 1.6.** jackson-jq's `$.field` form, which Kestra's own `SseRequest` example uses, does not parse; the task fails before sending, naming `concatJqExpression`. Write `.field`. No other difference was found on the cases tested (strings, integers, decimals, booleans, null, arrays, string indexing).
6. **Outputs are not masked.** As in Kestra and egret's plugin tasks, `outputs.*.body` and `outputs.*.headers` (with `Set-Cookie`) are stored as returned; a server that echoes a secret puts it in the output. Logs and failure messages are masked.
7. **Download re-claim idempotence** is shown by the stable naming (unit tests), not by running one run twice through the worker.
8. **`RefKind::Dataset`** has no task row any more but stays in `egret-workflow-api` and `refs.rs` (returns `None`).
