# Workflow package #4 "HTTP and the unserved platform tasks"

**Status:** designed 2026-10-28. Not built. Roadmap row #4 of `docs/en/plans/2026-10-18-workflow-kestra-parity-roadmap.md`. Plan: `docs/en/plans/2026-10-28-workflow-http.md`. Survey (with file:line for every claim): `docs/en/specs/2026-10-28-workflow-http-survey.md`. Branch `feat/workflow-http`. Kestra is the checkout at `data-portal/kestra`, `96893b58`.

## 1. Problem

`io.kestra.plugin.core.http.Request`, `Download` and `SseRequest` do not exist in egret, and six egret-only task rows are registered with no handler, so a flow using any of them is refused as `task_type_not_served`. Request is the most used core task after Log. The oracle has no http flow, so this package banks **0** entries; evidence is new unit and integration tests.

## 2. Decisions

User decisions, 2026-10-28 (asked, answered): **Q1** egress option A; **Q2** `secret()` resolves on the three http tasks in this package (not #10); **Q3** wire `egret.sql`, remove three rows, defer two. The rest are controller decisions under the autonomy rules, recorded here.

- **D1. Egress (Q1).** Handlers run in the egret process, so they share its network position (Postgres, the Kubernetes API, engine admin endpoints, cloud metadata; the task-pod NetworkPolicy does not cover that pod). Policy **A**: parse the URL with `url::Url`, allow only `http`/`https`, resolve once, require **every** address to be public, pin the vetted addresses (`ClientBuilder::resolve`), disable automatic redirects and follow them by hand (at most 10), **re-vetting every `Location`**, call `.no_proxy()`. A per-deployment host allowlist `workflow.http.allow_hosts` (exact, case-insensitive host match, as `automation.webhook_allow_hosts` does) lets an operator open a private API. This is a recorded **security divergence** from Kestra, which has no default block (survey §1.2, §5).
- **D2. One guard.** `egret-automation/src/deliver/destination.rs` moves to a small shared crate/module that both `egret-automation` and `egret-workflow` use (a port rule forbids workflow depending on automation). Its range list gains NAT64 `64:ff9b::/96`, 6to4 `2002::/16`, Teredo `2001::/32`, v4-compatible `::a.b.c.d` and the whole `0.0.0.0/8`. The allowlist stays host-exact; a listed name is trusted whatever it resolves to (documented).
- **D3. Allowlist.** A **separate** key `workflow.http.allow_hosts` (a different blast radius from alert webhooks). Env `EGRET_WORKFLOW__HTTP__ALLOW_HOSTS`. No per-workspace list now (follow-up, needs a never-allow set).
- **D4. Flow-controlled transport.** `options.proxy` is **refused** (a flow-chosen proxy defeats pinning); `options.ssl.insecureTrustAllCertificates: true` is **refused** (Kestra's `!= null` bug is not copied); `options.auth.type: DIGEST` is **refused** (reqwest has none); `encryptBody: true` is **refused**; a `uri` with userinfo (`user:password@host`) is **refused** (controller decision, Task C3), so credentials never reach the `uri` output. Each refusal is a publish-time finding and a run-time failure for stored flows, naming the reason. Any port is allowed.
- **D5. `secret()` (Q2).** Resolved on `Request`, `Download` and `SseRequest` through `render_with_secrets`, as the plugin path does; the `validate.rs` `secret_outside_plugin_task` exemption is extended to these three types; resolved values are masked in every log line and error. Credentials are never logged (`Authorization`, `Proxy-Authorization`, `Cookie`, `Set-Cookie`). On a cross-origin redirect the `Authorization` header is dropped.
- **D6. Request.** Properties and defaults as Kestra (`uri`, `method` default GET, `body`, `contentType`, `formData`, `headers`, `options.{timeout,auth BASIC|BEARER,followRedirects default true,allowFailed,allowedResponseCodes,logs}`). Outputs `uri` (the request URI), `code`, `headers`, `body` (string, never parsed as JSON). Body decoded as UTF-8 with Kestra's illegal-code-point error. The body cap is **1 MiB** (egret's render cap, `runners/env.rs:204`), not Kestra's 19 MiB, with Kestra's message adapted: it points at `Download`. The status rule is Kestra's (`HttpClient.isAllowedStatusCode`; controller decision, Task C3): a non-empty `allowedResponseCodes` replaces the rule (only the listed codes pass, also over `allowFailed`); else `allowFailed` passes every code; else **any code below 400 passes** (so an unfollowed 3xx succeeds). The `headers` output keeps every header as Kestra does, `Set-Cookie` included; headers are never logged except through `options.logs`, where credential headers are always `******`. A multipart body is capped by `workflow.storage.max_file_bytes` (1 MiB without `[storage]`). A failure message carries at most 4 KiB of the response body, masked.
- **D7. Download.** Streams to internal storage through `Outcome.files` (template: `egret.sql` STORE), under a **stable** per-run file name (`saveAs` honoured, `Content-Disposition` honoured, both sanitised to one path segment), so a re-claim overwrites its own object. Cap `workflow.http.max_download_bytes` (default 1 GiB; Kestra has none). `failOnEmptyResponse` default true; the `Content-Length` check is kept. Without `[storage]` it fails naming the missing config. Outputs `uri`, `code`, `length`, `headers`.
- **D8. SseRequest.** Kestra's parser semantics; JQ via `jaq` (not jackson-jq 1.6; differences listed in the plan's report when found). Divergences, recorded: a status of 400 or above **fails** (Kestra never checks), and a cap of `workflow.http.max_sse_events` (default 10 000) and the task `timeout:` stop a stream (Kestra has neither). Outputs `uri`, `events`, `size`, `result`.
- **D9. Registry.** The FQCN rows plus Kestra's aliases `io.kestra.plugin.fs.http.Request` and `...Download` (Kestra declares both). Tests that used `http.Request` as the example of an unregistered type move to another unregistered FQCN.
- **D10. The six unserved rows (Q3).** Wire **`egret.sql`**: build the query port before `handlers_for` (`main.rs:2289` vs `:2981`) and add the `RefKind::Database` ownership resolver, because publish refuses the type today (`refs.rs:95`). Accept the open `run_as` question as is (`created_by` is the principal; recorded). **Remove** `core.http`, `core.slack`, `egret.dataset.refresh`. **Defer** `egret.dataapi.call` and `egret.report.send` (they stay registered and refused as `task_type_not_served`; their schema texts are corrected). Removing a row changes only the error code for flows that could never run (`task_type_not_served` -> unknown type).
- **D11. Config.** `WorkflowConfig` gains `http.{allow_hosts, max_download_bytes, max_sse_events, max_redirects (10), connect_timeout}`; documented in the config reference and `.env.example`-style docs as the repo does for sibling keys.
- **D12. Out of scope.** `http.Trigger` (#11), per-workspace allowlist, a deployment-level egress proxy, `DIGEST`/`encryptBody` (refused), `options.logs` beyond redacted request/response lines.

## 3. Ratchet and tests

Expected oracle movement: **0**. `LIVE` 295 / `VALIDATE_REFUSED` 25 / `UNKNOWN_TYPE_REFUSED` 21 are re-measured. Tests use a local test server on `127.0.0.1`, so the suite sets the allowlist for it and has separate tests with it unset: loopback, link-local, a name that resolves to a private address, a redirect to a private address, a redirect with credentials crossing origin, userinfo in the URL, a non-http scheme. Plus: auth BASIC/BEARER, `formData`, `allowFailed`, `allowedResponseCodes`, body cap, Download re-claim idempotence and cap, empty response, SSE parse/JQ/cap/4xx, `secret()` masked in logs and errors, the refusals of D4 at publish, the footprint drift tests, `egret.sql` publish and run against a stub port.
