# DG debt Wave 2 — P2: tag-capable profiles from the console, and four small profile/SQL Lab fixes

Package P2 of the DG debt plan. Rows: GitHub #786 (KI-125), KI-135, KI-149, KI-267, KI-318.

## Rows

### 1. #786 / KI-125 — a console-made Trino profile can be given a tag service

**Backend.** New route `PUT /api/control-plane/policies/services/{service}/tag-service`, body
`{"tagService": "<tag profile>" | null}`, permission `policy:update`. It is the first `UPDATE` of
`policy.authz_services.config_jsonb` in `src/`, so it runs every guard the create path runs, on the
UPDATE, inside one transaction that row-locks the profile:

- the type rule (SP4d debt Task 2): only a `trino` profile may carry a `tagService`
  (`refuse_tag_service_on_non_trino_profile`; migration 0176's `CHECK` stays the schema bound);
- the value-shape rule (SP4d debt Task 9): a non-empty string, or `null` to remove it
  (`refuse_unnameable_tag_service`);
- the target rule (DG backend cleanup D / #673 follow-up): the named profile must exist and be of type
  `tag` (`refuse_tag_service_naming_a_non_tag_profile`), read in the same transaction.

**Decision (conservative): refuse, do not recompile.** A profile that an engine downloads (bound to any
engine) is refused with 409: changing its tag service would swap the whole `tagPolicies` block that
engine enforces, and the bind-time guard (`usable_tag_service` in `PUT /engines/{id}`) is the place where
a tag service is checked against an engine. Unbind the engine, change the tag service, bind again. A
`generated` profile (compiled by the permission model) is refused with 409 too: the compiler files its
tag rules into the tag service it reads at compile time, and the route does not recompile. So the route
reaches exactly the population #786 is about: an unbound, hand-made profile.

On success the profile's `policy_version` is bumped (its download embeds the tag service's policies), the
old and new tag services' `tag_version`s are bumped (their tag download resolves its owning profile through
the link), and one governance event `profile:tag_service` (resource `policy_profile`) is recorded in the
same transaction via `egret_audit::governance::record_change`, shown on Recent changes. Setting the value it
already has is a 200 that writes nothing.

**Frontend.** New profile: type adds **Tag**; a Trino profile gets a **Tag service** picker of existing
`tag` profiles (or *None*). **Decision (conservative): the picker does not create the tag profile in the
same submit.** It offers a **New tag profile** button that switches the dialog to a Tag profile named
`<name>_tag`; after it is created the dialog returns to the Trino profile with the new tag profile picked.
Two explicit creates, no half-made pair on a refusal. The unbound profile's **Advanced** tab gets a
**Tag service** section with the same picker and Save; on a bound or generated profile it is read-only
with the reason. The engine pickers (Register external engine, external engine Settings) mark a Trino
profile without a usable tag service as unbindable instead of letting the bind fail with 400.

### 2. KI-135 — Seed default policies says what happened

The success toast exists on main (#697) but disappears; the Advanced tab's empty text says the profile has
no manual policy, which is true (seeded rows are `infra`) but reads as "nothing happened". Fix: the result
stays on the tab as a status line (`role="status"`): *Added N default policies. They are egret-seeded, so
they are listed on Policies, not here.*, or why nothing was added (the profile already had policies). The
empty state names the egret-seeded and egret-compiled policies the profile has and points to Policies.
The server refusal of a non-Trino profile (SP4d-3, 400) is unchanged.

### 3. KI-149 — the Trino config warns about an unreachable download URL

SP4d-4 unified the renderer (`ranger_plugin_files`) but not the judgement. The loopback/unparseable check
(`download_url_problem`) moves from `egret-engine-mgmt`'s external route to
`egret_engine_mgmt_api::ranger_config::download_url_warning`, and both routes use it. The Trino route's body
becomes `{files, warnings}` (was a bare array; the console is its only caller and is updated). The
in-cluster-address warning stays external-only: `http://egret:8080` is right for an in-cluster engine.

### 4. KI-267 — the policy editor has an `h1`

FE-PAGE-7 allows an `sr-only` `h1` where the title is an input: the editor renders one naming the policy
(or *New access policy* etc.), and one in its loading, error and saved branches.

### 5. KI-318 — SQL Lab's timeout on a DDL statement says it may still complete

**Decision: message, not exemption.** Exempting rename holds would need a per-statement timeout longer than
the 90 s hold on both egret's wait and Trino's `query_max_run_time`, i.e. a second limit for a statement
class egret recognises by text; a wrong match would let any long query run past the operator's limit. The
message is the conservative fix: when the statement's first keyword is `ALTER`, `CREATE`, `DROP`, `RENAME`
or `TRUNCATE`, both timeout messages (egret's and Trino's own) add that SQL Lab stopped waiting but the
engine may still complete the change, and to check Governance → Recent changes (or list the tables) before
running it again. The 90 s hold is unchanged.
