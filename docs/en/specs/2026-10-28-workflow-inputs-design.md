# Workflow package #3 "Inputs checked at start"

**Status:** designed 2026-10-28. Not built. Roadmap row #3 of `docs/en/plans/2026-10-18-workflow-kestra-parity-roadmap.md`. Plan: `docs/en/plans/2026-10-28-workflow-inputs.md`. Branch `feat/workflow-inputs`. Two PRs: **#3a** (the start check, the save-time gaps, the harness seam) and **#3b** (the validate endpoint and the run form).

**Where the claims come from.** The survey is `docs/en/specs/2026-10-28-workflow-inputs-survey.md` (a copy of the read-only survey made 2026-10-28; every Kestra claim has file:line there). Kestra is the checkout at `data-portal/kestra`, `96893b58`, which is **newer than the pinned golden image**. FORM, `prefill`, `renderError` and the "a default must be required" rule may not exist in the image. Anything that depends on one of them says so.

## 1. Problem

egret stores the inputs as posted and coerces them at every render. No start path checks `required`, the type, `values`, `validator`, `min`/`max` or date bounds. Only backfill checks `required`, and the start checks FILE inputs. A bad input starts an execution that fails later at render, or runs with a wrong value (a BOOL `"yes"` stays a string). Kestra refuses the start (HTTP 422) and lists the problems in its `validate` endpoint.

## 2. Decisions (autonomy rules: decided by the controller 2026-10-28; recorded here)

- **D1. One checker, one chokepoint.** A pure module `inputs_check` takes the flow's `inputs:`, the posted object and a clock, and returns the resolved object or the **first** error in declared order. It is called from `start_execution_in_on` (`worker/claim.rs:3896`), after the object is normalised (≈ line 3936) and **before** `secret_inputs::split` (≈ 3943), because a SECRET `validator` must see the clear value. Kestra reports only the first bad input at start; so does egret (a superset would break the golden). The validate endpoint (D14) lists all of them.
- **D2. What is stored.** The **coerced** value, so a replay and every render see the typed value. Undeclared keys are dropped (Kestra drops them with a warning); the multipart route keeps its stricter 400 for an unknown or duplicated part. **Defaults are still filled at render**, as today (`render.rs` `with_declared_defaults`); they are validated at start when the default is a literal. A templated default (`{{`) is not validated at start and is listed in §6 as a gap.
- **D3. Messages.** The prefixed Kestra form is reproduced: ``Invalid value for input `<id>`. Cause: <cause>``, with Kestra's causes verbatim: ``it must match the pattern `<v>` ``, ``it must be more than `<min>` `` / ``it must be less than `<max>` ``, ``it must be after `<after>` `` / ``before``, ``It must be more than `<min>` `` for DURATION (capital I, as Kestra), ``it must match the values `[a, b]` ``, ``value `<x>` doesn't match the values `[A, B, C]` `` for MULTISELECT, ``Unable to parse array element as `<T>` on `<el>` ``, ``Cannot convert value '<v>' to <Class>`` (Java class names kept), `The input must be a valid email`. A missing required value is ``Missing required input:<id>`` (no space, as Kestra). Kestra's code-block wrapper for JSON/YAML/ION parse errors and its "encryption is not configured" text are **not** copied: a parse error uses the prefixed form. Status stays **400** with egret's `{"error": …}` body (Kestra: 422); recorded divergence. A webhook answers 400 with the message (Kestra: 422, empty body).
- **D4. Types** (parse, then validate, per the survey §1.3):
  - STRING: any scalar to its string; `validator` full-match. SECRET: same, on the clear value, before sealing.
  - INT: a JSON integer or an integer string that fits 32 bits; `1.0` as a string is refused, a JSON number with no fractional part is accepted. FLOAT: any finite number or numeric string (`NaN`/`Infinity` refused: **divergence**, they break JSON storage). `min`/`max` inclusive.
  - **BOOL: `true`/`false` (any case) or a JSON boolean; anything else is refused.** Kestra turns any other value into `false` silently; that is a wrong run, so this is a recorded **divergence**.
  - DATETIME (ISO instant), DATE, TIME, DURATION (ISO 8601, `PT…`/`P…D`): strict parse, `after`/`before`, `min`/`max`.
  - URI (must have a scheme), EMAIL (Kestra's regex, accepts empty), JSON (parse; `jsonSchema` in D12), YAML (parse), ION (parse), ARRAY and MULTISELECT (a JSON array or a JSON array string, each element parsed with `itemType`).
  - SELECT/MULTISELECT: `values` membership unless `allowCustomValue`. **A SELECT checks `values` only when `required` is true (Kestra's quirk, kept for parity)**; MULTISELECT always checks.
  - FILE: unchanged (`check_file_inputs`). FORM and REUSABLE_INPUTS: unchanged (not supported; the run form already disables them). The survey notes FORM is not `@EeOnly` in the newer source; checking the pinned image is a follow-up (§6).
- **D5. Empty string.** `""` is absent for every type except STRING, SELECT, EMAIL and SECRET (Kestra).
- **D6. `required` and `dependsOn`.** A null/absent value fails `required` (default `true`). `dependsOn.inputs`: an input is **disabled** unless every listed input is enabled and non-null; a disabled input is dropped and skips `required`. `dependsOn.condition` is rendered with the workflow renderer against `inputs` (the dependency values); only boolean `true` enables. An unknown dependency id is ignored at run time (Kestra) and refused at save (D11).
- **D7. Start paths.** Every path through `start_execution_in_on` is checked, except:
  - **Replay** (`replayed_from_execution_id` set) and **Loop/retry copies** are not re-checked (Kestra copies the stored inputs). Because D2 stores coerced values, re-checking would be idempotent anyway.
  - **Flow trigger**: Kestra does not validate these inputs (it renders them and fills defaults at render time). **egret follows Kestra: Flow-trigger fires are not checked.** The roadmap row said "flow-trigger start"; that goes beyond Kestra and is dropped. A bad value surfaces at render, as before. This also keeps the `born_failed` fire (which carries `{}`) working.
  - **Subflow child** has its own INSERT (`subflow.rs:514`): the same checker is called before `secret_inputs::split` there; a refusal fails the parent's Subflow run with `subflow inputs: <message>` (matches Kestra).
  - **Schedule fire / backfill tick**: the checker runs; a refusal keeps today's `Refused` handling. A save-time check of a schedule's literal inputs is a follow-up (§6).
- **D8. Harness seam.** `tests/executor.rs` gets a **start** seam: a start refused with `InvalidInput` is a `Refused`, not `Broken` (`oracle-exec/driver.rs:1175`). This banks `invalids/inputs-with-multiple-constraint-violations` (the golden message is compared by prefix and by the set of bad elements, since Kestra's order is a hash order).
- **D9. Time.** Date/time `after`/`before` compare to the parsed instants; no clock is read at start (defaults like `{{ now() }}` are templated and fall under D2's gap).
- **D10. Regex dialect.** `validator` uses `fancy-regex` (already in `Cargo.lock`, so no new transitive crate; it becomes a direct dependency of `egret-workflow`) with a backtrack limit instead of Kestra's 10 s timeout. Lookaround and backreferences work; possessive quantifiers and some Java-only syntax do not. The limit message is Kestra's ``the validator pattern `<v>` timed out — it may be too complex``.
- **D11. Save-time gaps** (in #3a): `dependsOn` naming an unknown input, `dependsOn` cycles, `defaults` together with `prefill`, a FILE `defaults` whose scheme is not `file`/`nsfile`, and a `validator` that does not compile (banks `invalids/inputs-bad-validator-syntax` **if** `fancy-regex` rejects `\` as Java does; measured in Task 5). **Not added:** "`defaults` needs `required: true`" (unverified in the pinned image; no corpus flow has `defaults` with `required: false`).
- **D12. `jsonSchema`.** Added only if a JSON Schema crate is already in the tree or is small and already approved in the dependency policy; otherwise it stays a `not_honoured` warning and moves to the follow-ups. Decided in Task 4 by measurement.
- **D13. SELECT/MULTISELECT `expression`.** Rendered at start with the workflow renderer; a failure is Kestra's ``Cannot render 'expression'`` error. `autoSelectFirst` fills the default with the first value. `isRadio` is a UI hint.
- **D14. The validate endpoint (#3b).** `POST /api/ws/{ws}/workflows/flows/{id}/executions/validate`, **JSON** body `{ "inputs": {…} }` (Kestra's is multipart; egret's run form already speaks JSON, and a FILE part is represented by its file name only). Stores nothing, uploads nothing. **Always 200** with Kestra's shape `{ id, namespace, inputs: [{ input, value, enabled, isDefault, errors: [{ message, renderError }] }], checks: [] }` (`checks` stays empty until package #16). 404 for a missing flow and 409 for a disabled one, as the start does.
- **D15. Run form (#3b).** The form keeps its client checks and adds: `min`/`max`, `after`/`before`, `validator` (shown, not evaluated in the browser), and it calls the validate endpoint on submit so one source of truth decides. Server errors are attached to the input named in the backticks (already so). The module comment saying "the server checks nothing" is rewritten. The `BackfillDialog` `"BOOLEAN"` typo (`BOOL`) is fixed in the same PR.
- **D16. Model.** `models::Input` gets `validator`, `min`, `max`, `after`, `before`, `values`, `expression`, `allow_custom_value`, `is_radio`, `auto_select_first`, `json_schema`, kept flat like `item_type`. The `not_honoured` warnings for the keys now honoured are removed; the key-treatment table (`spec/schema/property-treatment.json`) is updated; FORM's `inputs` and REUSABLE's `ref` stay warned.

## 3. Out of scope (named, with the package that lifts it)

Resume with `onResume` inputs and resume-validate (#9). Replay with new inputs (#7). `checks:` (#16). Templated defaults validated at start (follow-up, §6). FORM / REUSABLE_INPUTS. Local-path FILE inputs (deliberately not ported: they read the server's disk).

## 4. Expected ratchet

`invalids/inputs-with-multiple-constraint-violations` (D8) and, if D10 allows, `invalids/inputs-bad-validator-syntax`. Everything else must not move: **301 / 52 / 52 / 0 → 301 / 50 / 50 / 0** at best, 301 / 51 / 51 / 0 otherwise. Census `LIVE` 295 is unchanged.

## 5. Tests

A table test per type in `inputs_check` (valid, each error text, empty string, null). `dependsOn` enabled/disabled with `required`. One integration test per start path in D7 (API JSON, multipart, webhook, schedule, subflow child, replay not re-checked, Flow-trigger not checked, born-failed skip). The validate endpoint: always 200, every input listed, errors per input, nothing stored (row count unchanged). The drift tests (`openapi.json`, generated client) must pass. Frontend: the form's new checks and the server-error attribution.

## 6. Follow-ups recorded

Check FORM against the pinned image. Templated-default validation at start. A save-time check of a schedule's literal inputs. `jsonSchema` if D12 defers it. `defaults ⇒ required` if the pinned image has it. Webhook/API status 422 if a client ever needs Kestra's exact status.
