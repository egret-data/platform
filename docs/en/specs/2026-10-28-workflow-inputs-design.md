# Workflow package #3 "Inputs checked at start"

**Status:** designed 2026-10-28; #3a built and merged (#762); #3b built (Tasks B1-B3, PR in review). Roadmap row #3 of `docs/en/plans/2026-10-18-workflow-kestra-parity-roadmap.md`. Plan: `docs/en/plans/2026-10-28-workflow-inputs.md`. Branch `feat/workflow-inputs`. Two PRs: **#3a** (the start check, the save-time gaps, the harness seam) and **#3b** (the validate endpoint and the run form).

**Where the claims come from.** The survey is `docs/en/specs/2026-10-28-workflow-inputs-survey.md` (a copy of the read-only survey made 2026-10-28; every Kestra claim has file:line there). Kestra is the checkout at `data-portal/kestra`, `96893b58`, which is **newer than the pinned golden image**. FORM, `prefill`, `renderError` and the "a default must be required" rule may not exist in the image. Anything that depends on one of them says so.

## 1. Problem

egret stores the inputs as posted and coerces them at every render. No start path checks `required`, the type, `values`, `validator`, `min`/`max` or date bounds. Only backfill checks `required`, and the start checks FILE inputs. A bad input starts an execution that fails later at render, or runs with a wrong value (a BOOL `"yes"` stays a string). Kestra refuses the start (HTTP 422) and lists the problems in its `validate` endpoint.

## 2. Decisions (autonomy rules: decided by the controller 2026-10-28; recorded here)

- **D1. One checker, one chokepoint.** A pure module `inputs_check` takes the flow's `inputs:` and the posted object (no clock: D9), and returns the resolved object or the **first** error in declared order. It is called from `start_execution_in_on` (`worker/claim.rs:3896`), after the object is normalised (≈ line 3936) and **before** `secret_inputs::split` (≈ 3943), because a SECRET `validator` must see the clear value. Kestra reports only the first bad input at start; so does egret (a superset would break the golden). The validate endpoint (D14) lists all of them.
- **D2. What is stored.** The **coerced** value, so a replay and every render see the typed value. Undeclared keys are dropped (Kestra drops them with a warning); the multipart route keeps its stricter 400 for an unknown or duplicated part. **Defaults are still filled at render**, as today (`render.rs` `with_declared_defaults`); they are validated at start when the default is a literal. A templated default (`{{`) is not validated at start and is listed in §6 as a gap.
- **D3. Messages.** The prefixed Kestra form is reproduced: ``Invalid value for input `<id>`. Cause: <cause>``, with Kestra's causes verbatim: ``it must match the pattern `<v>` ``, ``it must be more than `<min>` `` / ``it must be less than `<max>` ``, ``it must be after `<after>` `` / ``before``, ``It must be more than `<min>` `` for DURATION (capital I, as Kestra), ``it must match the values `[a, b]` ``, ``value `<x>` doesn't match the values `[A, B, C]` `` for MULTISELECT, ``Unable to parse array element as `<T>` on `<el>` ``, ``Cannot convert value '<v>' to <Class>`` (Java class names kept), `The input must be a valid email`. A missing required value is ``Missing required input:<id>`` (no space, as Kestra). Kestra's code-block wrapper for JSON/YAML/ION parse errors and its "encryption is not configured" text are **not** copied: a parse error uses the prefixed form. Status stays **400** with egret's `{"error": …}` body (Kestra: 422); recorded divergence. A webhook answers 400 with the message (Kestra: 422, empty body).
- **D4. Types** (parse, then validate, per the survey §1.3):
  - STRING: any scalar to its string; `validator` full-match. SECRET: same, on the clear value, before sealing.
  - INT: a JSON integer or an integer string that fits 32 bits; `1.0` as a string is refused, a JSON number with no fractional part is accepted. FLOAT: any finite number or numeric string (`NaN`/`Infinity` refused: **divergence**, they break JSON storage). `min`/`max` inclusive.
  - **BOOL: `true`/`false` (any case) or a JSON boolean; anything else is refused.** Kestra turns any other value into `false` silently; that is a wrong run, so this is a recorded **divergence**.
  - DATETIME (ISO instant), DATE, TIME, DURATION (ISO 8601, `PT…`/`P…D`): strict parse, `after`/`before`, `min`/`max`.
  - URI (must have a scheme), EMAIL (Kestra's regex, accepts empty), JSON (parse; `jsonSchema` in D12), YAML (parse), ION (parse), ARRAY and MULTISELECT (a JSON array or a JSON array string, each element parsed with `itemType`).
  - SELECT/MULTISELECT: `values` membership unless `allowCustomValue`. **A SELECT checks `values` only when `required` is true (Kestra's quirk, kept for parity)**; MULTISELECT always checks.
  - FILE: unchanged (`check_file_inputs`). FORM and REUSABLE_INPUTS: unchanged (not supported; the run form already disables them). The survey notes FORM is not `@EeOnly` in the newer source; checking the pinned image is a follow-up (§6).
- **D5. Empty string.** `""` is absent for every type except STRING, SELECT, EMAIL and SECRET (Kestra).
- **D6. `required` and `dependsOn`.** A null/absent value fails `required` (default `true`). `dependsOn.inputs`: an input is **disabled** unless every listed input is enabled and non-null; a disabled input is dropped and skips `required`. `dependsOn.condition` is rendered with the workflow renderer against `inputs` (the dependency values); only boolean `true` enables. An unknown dependency id is ignored at run time (Kestra) and refused at save (D11).
- **D7. Start paths.** Every path through `start_execution_in_on` is checked, except:
  - **Replay** (`replayed_from_execution_id` set) and **Loop/retry copies** are not re-checked (Kestra copies the stored inputs). D2 stores coerced values, and checking a stored object again stores it unchanged: a JSON input whose value is a string is stored as that string's JSON text, so that this holds and the render reads it once (§7).
  - **Flow trigger**: Kestra does not validate these inputs (it renders them and fills defaults at render time). **egret follows Kestra: Flow-trigger fires are not checked.** The roadmap row said "flow-trigger start"; that goes beyond Kestra and is dropped. A bad value surfaces at render, as before. This also keeps the `born_failed` fire (which carries `{}`) working.
  - **Subflow child** has its own INSERT (`subflow.rs:514`): the same checker is called before `secret_inputs::split` there; a refusal fails the parent's Subflow run with `subflow inputs: <message>` (matches Kestra).
  - **Schedule fire / backfill tick**: the checker runs; a refusal keeps today's `Refused` handling. A save-time check of a schedule's literal inputs is a follow-up (§6).
- **D8. Harness seam.** `tests/executor.rs` gets a **start** seam: a start refused with `InvalidInput` is a `Refused`, not `Broken` (`oracle-exec/driver.rs:1175`). This banks `invalids/inputs-with-multiple-constraint-violations` (the golden message is compared by prefix and by the set of bad elements, since Kestra's order is a hash order).
- **D9. Time.** Date/time `after`/`before` compare to the parsed instants; no clock is read at start (defaults like `{{ now() }}` are templated and fall under D2's gap).
- **D10. Regex dialect.** `validator` uses `fancy-regex` (already in `Cargo.lock`, so no new transitive crate; it becomes a direct dependency of `egret-workflow`) with a backtrack limit instead of Kestra's 10 s timeout. Lookaround and backreferences work; possessive quantifiers and some Java-only syntax do not. The limit message is Kestra's ``the validator pattern `<v>` timed out — it may be too complex``.
- **D11. Save-time gaps** (in #3a): `dependsOn` naming an unknown input, `dependsOn` cycles, `defaults` together with `prefill`, a FILE `defaults` whose scheme is not `file`/`nsfile`, and a `validator` that does not compile (banks `invalids/inputs-bad-validator-syntax` **if** `fancy-regex` rejects `\` as Java does; measured in Task 5). **Not added:** "`defaults` needs `required: true`" (unverified in the pinned image; no corpus flow has `defaults` with `required: false`).
- **D12. `jsonSchema`.** Added only if a JSON Schema crate is already in the tree or is small and already approved in the dependency policy; otherwise it stays a `not_honoured` warning and moves to the follow-ups. Decided in Task 4 by measurement.
- **D13. SELECT/MULTISELECT `expression`.** Rendered at start with the workflow renderer; a failure is Kestra's ``Cannot render 'expression'`` error. `autoSelectFirst` fills the default with the first value. `isRadio` is a UI hint.
- **D14. The validate endpoint (#3b).** `POST /api/ws/{ws}/workflows/flows/{id}/executions/validate`, **JSON** body `{ "inputs": {…} }` (Kestra's is multipart; egret's run form already speaks JSON, and a FILE part is represented by its file name only). Stores nothing, uploads nothing. **Always 200** with Kestra's shape `{ id, namespace, inputs: [{ input, value, enabled, isDefault, errors: [{ message, renderError }] }], checks: [] }` (`checks` stays empty until package #16). 404 for a missing flow and 409 for a disabled one, as the start does.
- **D15. Run form (#3b).** The form keeps its client checks and adds: `min`/`max`, `after`/`before`, `validator` (shown, not evaluated in the browser), and it calls the validate endpoint on submit so one source of truth decides. Server errors are attached to the input named in the backticks (already so). The module comment saying "the server checks nothing" is rewritten. The `BackfillDialog` `"BOOLEAN"` typo (`BOOL`) is fixed in the same PR.
- **D16. Model.** `models::Input` gets `validator`, `min`, `max`, `after`, `before`, `values`, `expression`, `allow_custom_value`, `is_radio`, `auto_select_first`, `json_schema`, kept flat like `item_type`. The `not_honoured` warnings for the keys now honoured are removed; the key-treatment table (`spec/schema/property-treatment.json`) is updated; FORM's `inputs` and REUSABLE's `ref` stay warned.

Recorded from the whole-branch review of #3a (2026-10-28), not fixed in #3a:

- **Undeclared webhook and schedule keys (M3).** A webhook's or schedule's `inputs:` key the flow does not declare is dropped silently (D2), so a flow that read `{{ inputs.x }}` from it now fails at render. A save-time warning that compares the trigger's `inputs` keys with the flow's input ids would name it; Kestra only WARNs at run.
- **Orphaned uploads on a refused multipart start (M4).** The multipart start uploads FILE parts before its transaction (`routes.rs` ~2781-2836), so any input refusal leaves the blobs under an execution id that has no row. Pre-existing for the FILE-URI refusal; #3a widens it to every bad value posted next to a file. Check the text parts before streaming the files, or delete the uploads on `Err`.
- **A slow validator on an async worker (M5).** `check_validator` compiles the regex on every call and may spend up to `VALIDATOR_BACKTRACK_LIMIT` (1,000,000) steps (about 190 ms for `(a+)+\1b`) on the tokio worker, inside the start transaction. Bounded, so not a DoS; consider a lower limit, a compiled-regex cache or `spawn_blocking`.
- **Templated `defaults` render without `envs` or `labels` (M8).** The start renderer (`claim.rs` `checked_inputs`) binds only `flow`, `vars` and `inputs`, in the shared environment, so a depended-on templated default that uses `secret()` or `kv()` renders `None` and disables its dependents; Kestra would resolve it. No side effects and no secret reads; a recorded gap.

## 7. As built (2026-10-28, #3a)

What Tasks A1-A6 found differs from, or adds to, the decisions above. The decisions stay as the record; where they differ, this section governs.

- **`jsonSchema` (D12, D16).** Stays unchecked. `Cargo.lock` has no JSON Schema validator (`jsonschema`, `boon` and `valico` are absent), so nothing was added. It keeps its `not_honoured` warning, and `json_schema` was taken out of `models::Input` (D16 listed it): a modelled key that the flow schema does not serve broke `flow_schema`. A follow-up must re-add the field, the `input_keys` entry and the treatment entry together.
- **Absent optional input (D2).** `null` is stored for an optional input nobody posted (no `required`, no `defaults`, no `autoSelectFirst`), as Kestra does. Without it a Subflow reading `{{ inputs.x }}` failed under the strict renderer (`valids/subflow-nullable-input-parent`). Inputs with a default and disabled inputs are still left out.
- **`dependsOn` and defaults (D6).** An input disabled by `dependsOn` is dropped from the stored object, but the render still fills its declared default (Kestra drops it). Recorded divergence; fixing it needs a marker in the stored object or the render re-running `dependsOn`.
- **`autoSelectFirst` (D13).** The first option is stored as the value, an exception to D2 (a declared default stays unstored), because `render.rs` knows nothing of `autoSelectFirst`.
- **Flow-trigger starts (D7).** Identified by `flow_trigger_event_id` (migration 0157 sets it iff the trigger is a Flow record); no new field was added. `born_failed` is skipped as well, belt and braces.
- **Dates, times and durations (D4).** DATETIME, DATE, TIME and DURATION are parsed and bound-checked, and the **posted string** is stored (`P1D`, `10:00:00`, offsets kept). INT, FLOAT and BOOL are stored typed.
- **Save-time findings (D11).** Six codes, in `save_only_findings`, so they reach save and publish but **not** the run gate (a published version keeps running): `input_depends_on_unknown`, `input_depends_on_cycle`, `input_defaults_with_prefill`, `input_file_defaults_invalid`, `input_validator_invalid`, `input_bound_invalid`. `fancy-regex` rejects `\` as Java does, so `invalids/inputs-bad-validator-syntax` is banked at `Seam::Save`.
- **Bounds that do not parse (review I1).** `input_bound_invalid` refuses an INT / FLOAT / DURATION `min` or `max`, or a DATETIME / DATE / TIME `after` or `before`, that does not parse for its type, with the start check's cause (``input 'n': invalid `min`: Cannot convert value 'abc' to Integer``). Kestra's fields are typed, so Jackson refuses such a flow when it reads it. **Divergence:** Jackson's `ACCEPT_FLOAT_AS_INT` truncates an INT `min: 1.5` to `1`; egret refuses it at save. A stored flow that already holds such a bound keeps failing closed at start.
- **Validator anchoring (review I2, D10).** Save and start compile a `validator` with the same `inputs_check::anchored_validator`: the pattern as written first (as Java), then `\A(?:v)\z`, with a newline before the closing `)\z` only when `v`'s last line holds an extended-mode `#` comment. `(?x) [a-z]+ # letters` now works at start; a stored `abc)|(?:.*` fails closed instead of matching everything.
- **JSON string values (review M1, D2).** A JSON input whose parsed value is a string (`"123"` posted as text) is stored as that string's JSON text, because the render reads a JSON input's string as JSON (as it must for older rows and for the run form). Any other value is stored as parsed.
- **Backfill create (D7, review M7).** The create route runs the start check on the schedule's `inputs:` overlaid by the backfill's, after its own object / FILE / templated / required checks, so a value every tick would refuse is refused at create (with the start check's text) instead of ending the backfill at its first tick.
- **Live flows see parsed values (review M2).** New executions of existing flows change: YAML and ION inputs posted as text are now stored and rendered as **parsed objects** (before, `{{ inputs.y }}` printed the YAML text), and a STRING posted as a number is stored as a string. Rows written before #3a are untouched (`render.rs` is unchanged). The user docs (B3) must say so.
- **Oracle seam (D8).** `Seam::Start` was added to the oracle: a start refused with `InvalidInput` is `Ran::StartRefused`, and the golden 422 is compared as a multiset of lines. It banks `invalids/inputs-with-multiple-constraint-violations`.
- **Ratchet.** Measured **301 / 50 / 50 / 0**, `(301, 251, 50)` (§4).
- **Other.** A literal default is validated at start but not stored. A SELECT `values` check is skipped when there are no `values` and no `expression`. Undeclared keys are dropped on every checked path, so six existing tests that relied on them were changed. The client was regenerated with a borrowed `node_modules`; only the `spec` hash changed.

## 8. As built (#3b)

What Tasks B1 and B2 built, and what they left open. Where this differs from D14 and D15, this section governs.

### The validate endpoint (B1, D14)

- **Route.** `POST /api/ws/{ws}/workflows/flows/{id}/executions/validate`, body the same `StartExecutionRequest` as the start (JSON; an empty body is `{}`). Gate `WF_MANAGE`, then the start's flow lookup in the same order: 404 for a missing, trashed or foreign flow, 409 for a flow disabled by its column or by its YAML, 400 for a flow whose YAML does not parse. 400 also for a body that is not JSON or not an object, and for `inputs` that is not an object.
- **Always 200 for a checkable flow.** Shape: `{ id, namespace, inputs: [{ input, value, enabled, isDefault, errors: [{ message, renderError }] }], checks: [] }`. Every declared input is listed, with all of its errors (the start stops at the first bad input; this lists them all). `checks` is always empty. DTOs `ValidateInputsDto`, `InputValidationDto` and `InputErrorDto` are in the OpenAPI components, with an example.
- **`input`** is the input's entry from the draft's YAML **as written** (the first declaration of a repeated id). It is not egret's model and not Kestra's rendered `Input`: a SELECT `expression`'s rendered options are not echoed. The raw YAML carries a SECRET's literal `defaults`, which `GET flow` shows anyway.
- **`value`** is the parsed value, the literal default, or the raw posted value when it failed to parse; it falls back to the stored value. A JSON input whose value is a string shows the string, not the stored JSON text.
- **`enabled`** is `false` when `dependsOn` turns the input off for the posted values. **`isDefault`** is true when the value came from the default.
- **Masking.** A SECRET `value` is `******` whenever it is non-null, errors included. The SECRET `validator` cause is `<id>: it must match the pattern ...` and does not carry the value.
- **`errors`.** The errors of one input are merged into one entry joined with `\n` (Kestra's merged exception; the same text as the start's 400). `renderError` is `true` for a failing `dependsOn.condition` or a failing SELECT/MULTISELECT `expression`. A templated default that fails to render is not an error at start, so it never yields `renderError: true` here (consistent with the start, not with Kestra).
- **No side effects.** No execution row, no upload, no audit record (all asserted by tests). The renderer of the start check moved into `start_renderer(flow)` and `worker::input_outcomes` is `resolve_all` with it, so the two paths share one checker.
- **Checks that are skipped.** FILE readability (`check_file_inputs`) needs a row, and the start's plan and served-task refusals are not input checks; neither runs here. A valid answer therefore does not promise that the start will succeed.
- **Content-Type.** The body is read as bytes and parsed as JSON whatever the `Content-Type`; the start answers 415 for a type that is neither JSON nor multipart.

### The run form (B2, D15)

- **Run asks validate first.** On submit the form runs its own checks, then calls the validate endpoint with the start's JSON body (a chosen FILE goes as its file name; nothing is uploaded). Errors of **enabled** inputs that the form shows are placed beside their field, in the server's words, multi-line text kept. Errors of inputs the form has no control for (unsupported or undeclared) and of `enabled: false` inputs are ignored. If no showable error remains, the start is sent.
- **Validate never blocks.** Any validate failure (network, 4xx, 5xx, an odd body) falls back to the start, whose error is shown as before. The start is the final word.
- **`enabled: false` is noted, not hidden.** Validate runs only on submit, and whether `dependsOn` turns an input off depends on the other values, so hiding the field would need validate on change. The field gets a note in its help text ("With the values entered, the inputs it depends on turn this input off, so the run ignores it."), cleared on any edit.
- **Per-line attribution of the start's 400.** A refusal is split by line; a line goes to the declared input it names (``input `x` `` or `Missing required input:x`), a line naming none continues the previous one, and lines before any named one are form-level. `backfillForm.placeError` understands `Missing required input:x` too.
- **Client checks** (`inputModel.ts`, a first pass; the server decides). INT/FLOAT `min`/`max`; DURATION `min`/`max` compared as lengths; DATETIME, DATE and TIME `after`/`before` (TIME in seconds since midnight, so `17:30` equals `17:30:00`); all inclusive like `inputs_check`. SELECT membership only when `required` (the Kestra quirk of D4) and not `allowCustomValue`; MULTISELECT always unless `allowCustomValue`. A bound the form cannot parse is left to the server.
- **`validator` is server-only.** The form never evaluates it (the regex dialect differs); it shows "It must match the pattern ..." in the help text, as it shows the bounds ("From 10 to 20.", "At least ...", "On or after ...").
- **BackfillDialog.** `"BOOLEAN"` became `"BOOL"`. A schedule's `"true"`/`"false"` text (any case) now prefills the switch as a boolean; before, `"true"` showed off and was sent as `false`.

### Open follow-ups

- **Validate on change.** Each Run makes two requests (validate, then start). Validating while the user types would also let `dependsOn` hide or disable fields live.
- **Required check against `dependsOn`.** The client's `required` check runs before validate, so a required input that `dependsOn` turns off still blocks Run with "Enter a value". Fixing it needs validate before the client checks, or validate on change.
- **SELECT custom value.** The check honours `allowCustomValue`, but a SELECT is still a picker of `values`, so a custom value cannot be typed. The control was not redesigned.
- **`renderError` display.** An error with `renderError: true` (a broken `dependsOn.condition` or `expression`) is shown on the field like any other error, not as a problem in the flow definition.
- **Screenshots owed** for the user docs: the help lines with bounds and pattern, the inactive-input note, and validate errors under fields.
- **Still outside #3** (unchanged from §3 and §6): `jsonSchema`, FORM and REUSABLE_INPUTS, templated (`{{ }}`) defaults.
