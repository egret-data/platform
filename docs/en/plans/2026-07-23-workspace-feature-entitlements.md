# Per-workspace Feature Entitlements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a platform admin choose which of the five modules (SQL Lab, Datasets, Charts, Dashboards, Notebooks) each workspace may use at all, enforced in the backend and reflected in the UI.

**Architecture:** A `workspace_features` table where an absent row means enabled; a code-defined feature catalog mapping each module to the HTTP paths it owns; the gate itself inside `WsContext::from_request_parts`, which every workspace-scoped route already goes through. Chart execution is first split off the free-form `/queries` endpoint so that disabling SQL Lab stops arbitrary SQL without breaking the chart builder.

**Tech Stack:** Rust (axum 0.8, sqlx/Postgres, utoipa), React 18 + TypeScript, react-query, orval-generated API client, vitest, Playwright.

**Spec:** `docs/en/specs/2026-07-23-workspace-feature-entitlements-design.md`

```sql
-- Per-workspace feature entitlements (module on/off), set by platform admins.
--
-- An ABSENT ROW MEANS ENABLED. That is why this migration has no backfill:
-- every existing workspace keeps every module until an admin turns one off.
-- `feature` is TEXT validated against the code catalog in
-- `egret-workspace/src/features.rs`, not a Postgres enum, so adding a module
-- later needs no migration.
CREATE TABLE workspace_features (
    workspace_id UUID        NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    feature      TEXT        NOT NULL,
    enabled      BOOLEAN     NOT NULL,
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by   UUID        REFERENCES users(id) ON DELETE SET NULL,
    PRIMARY KEY (workspace_id, feature)
);

-- The hot path is "which features are OFF for this workspace", run on every
-- workspace-scoped request that touches a gated module.
CREATE INDEX workspace_features_disabled_idx
    ON workspace_features (workspace_id)
    WHERE enabled = false;
```

```rust
//! Per-workspace feature entitlements: the code-defined catalog of modules, the
//! request-path matcher that says which module a request belongs to, and the
//! `WorkspaceRepo` queries that read and write the on/off rows.
//!
//! An **absent row means enabled**. Only explicit `enabled = false` rows turn a
//! module off, so a fresh install and every pre-existing workspace behave
//! exactly as they did before this feature existed.

use std::collections::HashSet;

use egret_core::{Error, Result, UserId, WorkspaceId};

use crate::workspaces::{db_err, WorkspaceRepo};

/// Every module key, in the order the UI lists them.
pub const FEATURE_KEYS: &[&str] = &["sql_lab", "datasets", "charts", "dashboards", "notebooks"];

/// True if `key` names a module in the catalog.
pub fn is_known(key: &str) -> bool {
    FEATURE_KEYS.contains(&key)
}

impl WorkspaceRepo {
    /// The module keys explicitly turned OFF for `ws`. Everything not in the
    /// returned set is on.
    pub async fn disabled_features(&self, ws: WorkspaceId) -> Result<HashSet<String>> {
        let rows: Vec<(String,)> = sqlx::query_as(
            "SELECT feature FROM workspace_features \
             WHERE workspace_id = $1 AND enabled = false",
        )
        .bind(ws.0)
        .fetch_all(&self.db.pool)
        .await
        .map_err(db_err)?;
        Ok(rows.into_iter().map(|(f,)| f).collect())
    }

    /// Upsert `updates` for `ws` in one transaction. Rejects unknown keys before
    /// writing anything, so a batch containing a typo changes nothing.
    pub async fn set_features(
        &self,
        ws: WorkspaceId,
        updates: &[(String, bool)],
        actor: Option<UserId>,
    ) -> Result<()> {
        for (key, _) in updates {
            if !is_known(key) {
                return Err(Error::InvalidInput(format!("unknown feature: {key}")));
            }
        }
        let mut tx = self.db.pool.begin().await.map_err(db_err)?;
        for (key, enabled) in updates {
            sqlx::query(
                "INSERT INTO workspace_features (workspace_id, feature, enabled, updated_by) \
                 VALUES ($1, $2, $3, $4) \
                 ON CONFLICT (workspace_id, feature) DO UPDATE \
                 SET enabled = EXCLUDED.enabled, \
                     updated_at = now(), \
                     updated_by = EXCLUDED.updated_by",
            )
            .bind(ws.0)
            .bind(key)
            .bind(enabled)
            .bind(actor.map(|u| u.0))
            .execute(&mut *tx)
            .await
            .map_err(db_err)?;
        }
        tx.commit().await.map_err(db_err)?;
        Ok(())
    }
}
```

```rust
/// How a rule's `path` is compared against a request's path suffix.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Match {
    /// The suffix equals `path`, or starts with `path` followed by `/`.
    Prefix,
    /// The suffix equals `path` exactly.
    Exact,
}

/// One gated HTTP surface under `/api/ws/{workspace}/`.
#[derive(Debug, Clone, Copy)]
pub struct GateRule {
    pub path: &'static str,
    pub kind: Match,
    /// Uppercase HTTP methods this rule covers; `None` = every method.
    pub methods: Option<&'static [&'static str]>,
}

/// A module a workspace can be entitled to.
#[derive(Debug, Clone, Copy)]
pub struct Feature {
    pub key: &'static str,
    pub label: &'static str,
    pub description: &'static str,
    pub rules: &'static [GateRule],
}

const fn prefix(path: &'static str) -> GateRule {
    GateRule { path, kind: Match::Prefix, methods: None }
}

pub const FEATURES: &[Feature] = &[
    Feature {
        key: "sql_lab",
        label: "SQL Lab",
        description: "Write and run free-form SQL, browse engine schemas, and save queries.",
        rules: &[
            prefix("sqllab"),
            // Submitting free-form SQL. Reading back, listing, and cancelling
            // stay open: the chart builder runs through those same paths.
            GateRule { path: "queries", kind: Match::Exact, methods: Some(&["POST"]) },
        ],
    },
    Feature {
        key: "datasets",
        label: "Datasets",
        description: "Model physical tables and SQL into reusable datasets with metrics.",
        rules: &[prefix("datasets")],
    },
    Feature {
        key: "charts",
        label: "Charts",
        description: "Build and view charts on top of datasets.",
        rules: &[prefix("charts")],
    },
    Feature {
        key: "dashboards",
        label: "Dashboards",
        description: "Arrange charts into dashboards with filters and tabs.",
        rules: &[prefix("dashboards")],
    },
    Feature {
        key: "notebooks",
        label: "Notebooks",
        description: "Python and SQL notebooks backed by a per-user kernel.",
        rules: &[
            prefix("notebooks"),
            prefix("kernel"),
            prefix("notebook-runtime"),
            prefix("notebook-settings"),
        ],
    },
];

/// Workspace-scoped first path segments that are deliberately never gated.
///
/// `folders` and `objects` are content-type-neutral (a folder holds charts *and*
/// notebooks; `objects` is the sharing surface) and are already authorized
/// per-object by the PDP. The rest are workspace administration, which must keep
/// working no matter which modules are switched off — otherwise an admin could
/// lock themselves out of the settings that turn a module back on.
pub const UNGATED: &[&str] = &[
    "access-requests",
    "databases",
    "engines",
    "folders",
    "members",
    "objects",
    "roles",
    "shares",
];

/// The part of a request path after `/api/ws/{slug}/`, or `None` if the path is
/// not workspace-scoped.
///
/// Accepts the path with or without the leading `/api`: axum's `nest("/api", …)`
/// strips the prefix from the inner router's view of the URI, and we want the
/// same answer either way.
pub fn ws_path_suffix(path: &str) -> Option<&str> {
    let rest = path.strip_prefix("/api").unwrap_or(path);
    let rest = rest.strip_prefix("/ws/")?;
    let (_slug, suffix) = rest.split_once('/')?;
    if suffix.is_empty() {
        return None;
    }
    Some(suffix)
}

/// The feature key gating `suffix` for `method`, or `None` when the surface is
/// ungated. `method` is the uppercase HTTP method (`parts.method.as_str()`).
///
/// When several rules match, the one with the longest `path` wins, so a specific
/// sub-path can override a broader prefix without reordering the catalog.
pub fn gated_feature(suffix: &str, method: &str) -> Option<&'static str> {
    let mut best: Option<(usize, &'static str)> = None;
    for feature in FEATURES {
        for rule in feature.rules {
            let path_matches = match rule.kind {
                Match::Exact => suffix == rule.path,
                Match::Prefix => {
                    suffix == rule.path
                        || (suffix.len() > rule.path.len()
                            && suffix.starts_with(rule.path)
                            && suffix.as_bytes()[rule.path.len()] == b'/')
                }
            };
            if !path_matches {
                continue;
            }
            if let Some(methods) = rule.methods {
                if !methods.contains(&method) {
                    continue;
                }
            }
            // Written as a match rather than `map_or` so clippy's pedantic
            // lints (CI runs with `-D warnings`) have nothing to say.
            match best {
                Some((len, _)) if rule.path.len() <= len => {}
                _ => best = Some((rule.path.len(), feature.key)),
            }
        }
    }
    best.map(|(_, key)| key)
}
```

```rust
//! Every workspace-scoped route must be classified by the feature catalog:
//! either a module owns it, or it is explicitly listed as ungated.
//!
//! The gate lives in one place (`WsContext`), which only works if the catalog
//! knows about every route. This test is what keeps that true — add a route
//! under `/api/ws/{workspace}/` without declaring it and this fails.
//!
//! No database and no network: it reads the in-process OpenAPI document.

use std::collections::BTreeSet;

use egret_workspace::features::{gated_feature, ws_path_suffix, UNGATED};

#[test]
fn every_workspace_scoped_route_is_classified() {
    let doc = egret_server::openapi_doc();

    let mut unclassified = BTreeSet::new();
    for path in doc.paths.paths.keys() {
        let Some(suffix) = ws_path_suffix(path) else {
            continue;
        };
        let first = suffix.split('/').next().unwrap();
        if UNGATED.contains(&first) {
            continue;
        }
        // A route counts as claimed if ANY method is gated on it: `queries` is
        // gated for POST only, and that is a deliberate classification, not an
        // omission.
        let claimed = ["GET", "POST", "PUT", "PATCH", "DELETE"]
            .iter()
            .any(|m| gated_feature(suffix, m).is_some());
        if !claimed {
            unclassified.insert(first.to_string());
        }
    }

    assert!(
        unclassified.is_empty(),
        "these workspace-scoped path segments are in neither a Feature nor UNGATED: {unclassified:?}\n\
         Add them to crates/egret-workspace/src/features.rs — either to the module that owns them, \
         or to UNGATED if they must stay reachable when every module is off."
    );
}
```

```rust
/// Run a client-supplied `QuerySpec` against a dataset and return the rows.
///
/// This is `ch_run` for a spec that is not (yet) a saved chart: the chart
/// builder's preview, dashboard edit-mode cards, and filter-value dropdowns. It
/// exists so those three do not have to go through the free-form SQL endpoint —
/// which lets `POST /queries` be gated on the SQL Lab entitlement without
/// breaking chart authoring, and stops raw SQL crossing the wire when a user is
/// only building a chart.
///
/// Authorization is workspace-scoped `CH_READ`, exactly like the `ch_data`
/// build-only endpoint it replaces. It is deliberately NOT object-scoped: there
/// is no chart id to resolve, so an object guest cannot reach it — guests keep
/// using `ch_run` (`/charts/{id}/data`), which is object-scoped.
#[utoipa::path(
    post,
    path = "/api/ws/{workspace}/charts/run",
    tag = "charts",
    params(("workspace" = String, Path, description = "Workspace slug")),
    request_body = ChartDataBody,
    responses(
        (status = 200, description = "Query result", body = ChartRunResponse),
        (status = 400, description = "Invalid spec", body = ErrorBody),
        (status = 401, description = "Not authenticated", body = ErrorBody),
        (status = 403, description = "Missing permission or module disabled", body = ErrorBody),
        (status = 404, description = "Dataset not found in this workspace", body = ErrorBody),
        (status = 500, description = "Internal error", body = ErrorBody),
    ),
)]
async fn ch_run_spec(
    State(st): State<BiState>,
    WsContext(ctx): WsContext,
    Json(b): Json<ChartDataBody>,
) -> Result<Json<ChartRunResponse>, BiApiError> {
    egret_core::authz::require(&*st.pdp, &ctx, CH_READ)
        .await
        .map_err(BiApiError::from)?;

    let (sql, database_id) = compile_chart_sql(&st, &ctx, b.dataset_id, &b.query_spec).await?;
    let (session_user, bearer) = resolve_delegation(&st, &ctx, database_id).await?;
    let result = egret_query::execution::run_query(
        &st.databases,
        &egret_query::execution::connector::DefaultConnectorFactory,
        database_id,
        &sql,
        Some(b.query_spec.row_limit.max(0) as usize),
        session_user,
        bearer,
        &chart_run_limits(),
        tokio_util::sync::CancellationToken::new(),
    )
    .await
    .map_err(|e| BiApiError::from(crate::BiError::from(e)))?;

    Ok(Json(ChartRunResponse {
        columns: result.columns,
        rows: result.rows,
    }))
}
```

```ts
import { useQuery } from "@tanstack/react-query";
import { chartsChRunSpec } from "@/api/generated/charts/charts";
import type { QuerySpec } from "@/api/charts";

export interface SpecData {
  columns: { name: string; type: string }[];
  rows: unknown[][];
  isLoading: boolean;
  error: string | null;
}

/**
 * Run a `QuerySpec` against a dataset and return the rows.
 *
 * Replaces the old build -> submit -> poll pipeline that went through the
 * free-form SQL endpoint (`POST /queries`). That endpoint is now gated on the
 * SQL Lab entitlement, and chart work must keep working in a workspace where
 * SQL Lab is switched off — so it goes through `POST /charts/run`, which
 * compiles and executes the spec server-side in one request.
 */
export function useSpecData(
  ws: string,
  datasetId: string | null,
  spec: QuerySpec | null,
  enabled: boolean,
  nonce?: number,
): SpecData {
  const key = datasetId && spec ? JSON.stringify(spec) : "";
  const q = useQuery({
    queryKey: ["chartsChRunSpec", ws, datasetId, key, nonce],
    enabled: enabled && !!datasetId && !!spec,
    queryFn: async () =>
      (await chartsChRunSpec(ws, { dataset_id: datasetId!, query_spec: spec! } as never)).data as {
        columns: { name: string; type: string }[];
        rows: unknown[][];
      },
  });

  return {
    columns: q.data?.columns ?? [],
    rows: q.data?.rows ?? [],
    isLoading: q.isFetching,
    error: q.error ? String(q.error) : null,
  };
}
```

```ts
export function useColumnValues(
  ws: string,
  datasetId: string | null,
  column: string | null,
  enabled: boolean,
  filters: ChartFilter[] = [],

  // Select the column directly rather than as a group-by dimension: the engine

  // spec is rejected (400). Rows are deduped client-side below, so a plain

    () => Array.from(new Set(data.rows.map((r) => r[0]).filter((v) => v != null).map(String))),

  );
```

```rust
pub struct FeatureDto {

    pub label: String,
    pub description: String,
    pub enabled: bool,

    pub features: std::collections::BTreeMap<String, bool>,

        (status = 401, description = "Not authenticated", body = ErrorBody),

        (status = 500, description = "Internal error", body = ErrorBody),
    ),

async fn ws_features(
    State(st): State<WorkspaceState>,
    Auth(p): Auth,
    Path(id): Path<Uuid>,
) -> Result<Json<Vec<FeatureDto>>, AuthError> {
    egret_core::authz::require(&*st.pdp, &p, "workspace:read")
        .await
        .map_err(AuthError)?;
    let disabled = st
        .workspaces
        .disabled_features(WorkspaceId(id))
        .await
        .map_err(AuthError)?;
    Ok(Json(
        crate::features::FEATURES
            .iter()
            .map(|f| FeatureDto {
                key: f.key.to_string(),
                label: f.label.to_string(),
                description: f.description.to_string(),
                enabled: !disabled.contains(f.key),
            })
            .collect(),
    ))
}

#[utoipa::path(
    put,
    path = "/api/admin/workspaces/{id}/features",
    tag = "admin-workspaces",
    params(("id" = String, Path, description = "Workspace id")),
    request_body = SetFeatures,
    responses(
        (status = 200, description = "Updated entitlements", body = Vec<FeatureDto>),
        (status = 400, description = "Unknown feature key", body = ErrorBody),
        (status = 401, description = "Not authenticated", body = ErrorBody),
        (status = 403, description = "Missing platform permission", body = ErrorBody),
        (status = 500, description = "Internal error", body = ErrorBody),
    ),
)]
async fn set_ws_features(
    State(st): State<WorkspaceState>,
    Auth(p): Auth,
    Path(id): Path<Uuid>,
    Json(body): Json<SetFeatures>,
) -> Result<Json<Vec<FeatureDto>>, AuthError> {
    egret_core::authz::require(&*st.pdp, &p, "workspace:update")
        .await
        .map_err(AuthError)?;

    let ws = WorkspaceId(id);
    let before = st.workspaces.disabled_features(ws).await.map_err(AuthError)?;

    let updates: Vec<(String, bool)> = body.features.into_iter().collect();
    st.workspaces
        .set_features(ws, &updates, Some(p.user_id))
        .await
        .map_err(AuthError)?;

    let after = st.workspaces.disabled_features(ws).await.map_err(AuthError)?;

    // Best-effort audit: entitlement changes alter what a whole workspace can
    // do, so who did it and what changed must be recoverable.
    st.audit.emit(egret_audit::AuditEvent::Mutation {
        actor_user_id: Some(p.user_id.0),
        workspace_id: Some(id),
        action: "workspace.features.update".into(),
        resource_type: "workspace".into(),
        resource_id: Some(id.to_string()),
        detail: serde_json::json!({
            "disabled_before": before.iter().collect::<Vec<_>>(),
            "disabled_after": after.iter().collect::<Vec<_>>(),
        }),
    });

    Ok(Json(
        crate::features::FEATURES
            .iter()
            .map(|f| FeatureDto {
                key: f.key.to_string(),
                label: f.label.to_string(),
                description: f.description.to_string(),
```

```rust
        &self,

            std::collections::HashMap::new();

            out.entry(ws).or_default().insert(feature);
```

```tsx
import { Button } from "@/components/ui/button";
import { Switch } from "@/components/ui/switch";
import { useSetWorkspaceFeatures, useWorkspaceFeatureList } from "@/api/features";

/**
 * Which modules this workspace may use at all.
 *
 * This is an entitlement, not a permission: it applies to everyone in the
 * workspace, platform admins included. Read/write depth inside a module is
 * still decided by workspace roles.
 */
export function WorkspaceFeaturesTab({ workspaceId }: { workspaceId: string }) {
  const { data, isLoading } = useWorkspaceFeatureList(workspaceId);
  const save = useSetWorkspaceFeatures(workspaceId);
  const [draft, setDraft] = useState<Record<string, boolean>>({});

  useEffect(() => {
    if (data) setDraft(Object.fromEntries(data.map((f) => [f.key, f.enabled])));
  }, [data]);

  if (isLoading || !data) return <p className="text-sm text-muted-foreground">Loading…</p>;

  const dirty = data.some((f) => draft[f.key] !== f.enabled);

  async function onSave() {
    try {
      await save.mutateAsync({ features: draft });
      toast.success("Features updated");
    } catch (e) {
      toast.error(String(e));
    }
  }

  return (
    <div className="space-y-4">
      <p className="text-sm text-muted-foreground">
        Modules this workspace can use. Turning one off hides it for everyone in the workspace and
        blocks its API; existing content is kept and comes back when you turn it on again.
      </p>

      <div className="divide-y divide-border rounded-md border border-border">
        {data.map((f) => (
          <div key={f.key} className="flex items-start justify-between gap-4 p-3">
            <div>
              <div className="text-sm font-medium">{f.label}</div>
              <div className="text-sm text-muted-foreground">{f.description}</div>
            </div>

              checked={draft[f.key] ?? f.enabled}
              onCheckedChange={(v) => setDraft((d) => ({ ...d, [f.key]: v }))}
            />
          </div>
        ))}
      </div>

      <Button size="sm" disabled={!dirty || save.isPending} onClick={onSave}>
        {save.isPending ? "Saving…" : "Save"}
      </Button>
    </div>
  );
```

Create `frontend/src/hooks/useWorkspaceFeatures.ts`:

```ts
import { useParams } from "react-router-dom";
import { useMyWorkspaces } from "@/api/hooks";

/**
 * Module keys the workspace in the current route has switched on.
 *
 * Returns every key while the list is still loading, so the nav does not flash
 * items away and back on first paint. The backend is the real gate, so an
 * optimistic UI here is safe.
 */
export function useWorkspaceFeatures(): string[] {
  const { workspace } = useParams();
  const { data } = useMyWorkspaces();
  if (!data) return ALL_FEATURES;
  return data.find((w) => w.slug === workspace)?.features ?? ALL_FEATURES;
}

const ALL_FEATURES = ["sql_lab", "datasets", "charts", "dashboards", "notebooks"];
```

```tsx
import type { ReactNode } from "react";

/**
 * Blocks a route whose module is switched off for this workspace. The backend
 * returns 403 regardless; this exists so a bookmarked or hand-typed URL shows
 * an explanation instead of a failed request.
 */
export function RequireFeature({ name, children }: { name: string; children: ReactNode }) {
  const features = useWorkspaceFeatures();
  if (!features.includes(name)) return <Forbidden />;
```

## Notes for the reviewer

Two decisions in this plan are worth a second look, both recorded in the spec:

1. **The gate lives in `WsContext`, not a middleware layer.** That couples workspace resolution with entitlement checking in one extractor. The payoff is that coverage holds by construction — a workspace-scoped route cannot exist without `WsContext` — and the workspace is already loaded, so there is no second slug lookup. The route-coverage test in Task 3 is what keeps the catalog honest.

2. **An unmatched path is allowed, not denied.** Failing closed on a route nobody classified would turn a catalog omission into a production outage. The omission is caught at test time instead, which is the right place for it.
