# C1 — Declarative Parameter Constraints Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An endpoint author can declare bounds, lengths, a regex and date ranges on a parameter, and both publish and serving enforce them from one place.

**Architecture:** Every constraint lives inside `serving::params::coerce`, which publish already calls to validate an author's `default`. That single shared function is what makes publish and serving agree by construction rather than by two checks that can drift. Constraints are declarative fields on `ParamSpec` — no script runtime.

**Tech Stack:** Rust, `serde` with `deny_unknown_fields`, the `regex` crate (finite automata, no backtracking), `utoipa` for OpenAPI, React + orval-generated client.

**Spec:** `docs/en/specs/2026-08-26-dataapi-parameter-constraints-design.md` (VI mirror alongside). Read §2, §2.1, §2.2 and §3 before Task 1 — they carry decisions that look like bugs if you meet them cold.

## Global Constraints

- **`coerce` is the only place a constraint may be enforced.** Not beside it, not in a second pass in the router. This is what makes publish and serving agree; a second check is the defect this design exists to prevent.
- **No parameter name, bound, or constraint kind may appear in a 400.** `ServingError::ParamInvalid` and `ParamMissing` stay unit variants carrying nothing. `serving/error.rs` documents why and enforces it by shape. Publish-time errors (`ValidationError`) are the opposite — they are the author reading about their own endpoint and should be specific.
- **Publish's probe values deliberately violate these constraints.** `representative_value` yields `Param::I64(1)` even under `minimum: 100`. Do not "fix" it: probes decide which branches a definition takes, and branches are what M1 freezes as the endpoint's column union.
- **Lengths count Unicode scalars, not bytes.** `String::len()` in Rust is bytes and is the wrong answer.
- **`pattern` must be anchored** so the whole value must match, and an author who writes their own `^…$` must get the same answer.
- **The single-statement gate is untouchable.** `#` forbidden; `;` rejected at `reject_unscannable_bytes`, at the comment/literal scan, and after render. `git diff <base>..HEAD -- crates/egret-dataapi/tests/template_render.rs` must stay **0 bytes**.
- `openapi.json` is committed and asserted **byte-for-byte by the `egret-server` crate** — a different crate from the one being edited.
- Regenerate the frontend client with **`npm run gen:api`**, never bare `orval` (the npm script runs a committed codemod that bare orval skips).
- Tests read `DATABASE_URL`; export `postgres://egret:egret@localhost:5432/egret_test`. Never the dev `egret` database. The dev DB's migration-127 drift must not be repaired.
- Frontend: suite green, `tsc --noEmit` clean, eslint **177 warnings, 0 errors**.
- `cargo fmt` + `cargo clippy --all-targets` clean. Conventional Commits.

```rust
/// The compiled size a parameter's `pattern` may reach.
///
/// `regex`'s own default is 10 MB. A validation rule on an endpoint parameter
/// that needs megabytes of compiled program is not a validation rule, and the
/// cap is here rather than at serve time so an author learns at publish.
pub const MAX_PATTERN_PROGRAM_BYTES: usize = 64 * 1024;

/// Compile a `pattern` the way `coerce` will, so publish and serving cannot
/// disagree about which patterns exist.
///
/// **Anchored here, once.** The anchors are added in this one function, so a
/// pattern accepted at publish is byte-identical to the one matched at serve.
/// An author's own `^…$` is idempotent under it.
pub fn compile_pattern(pattern: &str) -> Result<regex::Regex, regex::Error> {
    regex::RegexBuilder::new(&format!("^(?:{pattern})$"))
        .size_limit(MAX_PATTERN_PROGRAM_BYTES)
        .build()
}

/// Refuse a constraint set that cannot be honoured, before anything tries to.
///
/// # Why this runs before `check_defaults`
///
/// `check_defaults` validates the author's `default` through `coerce`, and
/// `coerce` enforces these constraints. If the set itself is malformed — a
/// `minimum` above its `maximum` — the author would be told their `default` is
/// wrong when the default is the one part that is fine.
pub fn check_constraints(params: &[ParamSpec]) -> std::result::Result<(), ValidationError> {
    for p in params {
        let ty = type_name(&p.ty);

        // Which constraints this type can carry at all. A `pattern` on a
        // `Boolean` is not harmless noise: it teaches the author a model where
        // constraints apply everywhere, and the next one they write silently
        // does nothing.
        let numeric = matches!(p.ty, ParamType::Number);
        let textual = matches!(p.ty, ParamType::String);
        let temporal = matches!(p.ty, ParamType::Date | ParamType::Timestamp);

        for (present, allowed_here, name) in [
            (p.minimum.is_some(), numeric, "minimum"),
            (p.maximum.is_some(), numeric, "maximum"),
            (p.min_length.is_some(), textual, "min_length"),
            (p.max_length.is_some(), textual, "max_length"),
            (p.pattern.is_some(), textual, "pattern"),
            (p.not_before.is_some(), temporal, "not_before"),
            (p.not_after.is_some(), temporal, "not_after"),
        ] {
            if present && !allowed_here {
                return Err(ValidationError::ConstraintNotForType {
                    param: p.name.clone(),
                    constraint: name,
                    ty,
                });
            }
        }

        // Inverted bounds. Equal bounds are legitimate — a parameter pinned to
        // one value — so this is strictly greater, never "not less".
        if let (Some(lo), Some(hi)) = (&p.minimum, &p.maximum) {
            if compare_decimal_text(lo, hi) == std::cmp::Ordering::Greater {
                return Err(ValidationError::BoundsInverted {
                    param: p.name.clone(),
                    constraint: "minimum",
                });
            }
        }
        if let (Some(lo), Some(hi)) = (p.min_length, p.max_length) {
            if lo > hi {
                return Err(ValidationError::BoundsInverted {
                    param: p.name.clone(),
                    constraint: "min_length",
                });
            }
        }
        if let (Some(lo), Some(hi)) = (&p.not_before, &p.not_after) {
            if lo.as_str() > hi.as_str() {
                return Err(ValidationError::BoundsInverted {
                    param: p.name.clone(),
                    constraint: "not_before",
                });
            }
        }

        if let Some(pattern) = &p.pattern {
            match compile_pattern(pattern) {
                Ok(_) => {}
                Err(regex::Error::CompiledTooBig(_)) => {
                    return Err(ValidationError::PatternTooLarge { param: p.name.clone() })
                }
                Err(e) => {
                    return Err(ValidationError::PatternInvalid {
                        param: p.name.clone(),
                        detail: e.to_string(),
                    })
                }
            }
        }
    }
    Ok(())
}
```

```rust
/// Compare two decimal texts without going through a float.
///
/// `coerce` refuses to put a decimal through an `f64` because a decimal that
/// round-trips through a float stops comparing equal to itself on the engine.
/// A bound compared as a float would reintroduce that on this side: a `minimum`
/// of `"0.3"` would reject the value `"0.3"`.
///
/// Both sides have already passed `is_plain_decimal` or are an author's bound
/// that `check_constraints` accepted, so the grammar is `-?digits[.digits]`.
pub(crate) fn compare_decimal_text(a: &str, b: &str) -> std::cmp::Ordering {
    use std::cmp::Ordering;
    let (a_neg, a_body) = a.strip_prefix('-').map_or((false, a), |r| (true, r));
    let (b_neg, b_body) = b.strip_prefix('-').map_or((false, b), |r| (true, r));
    match (a_neg, b_neg) {
        (false, true) => return Ordering::Greater,
        (true, false) => return Ordering::Less,
        _ => {}
    }
    let flip = |o: Ordering| if a_neg { o.reverse() } else { o };

    let split = |s: &str| {
        let mut it = s.splitn(2, '.');
        let int = it.next().unwrap_or("0").to_string();
        let frac = it.next().unwrap_or("").to_string();
        (int, frac)
    };
    let (a_int, a_frac) = split(a_body);
    let (b_int, b_frac) = split(b_body);

    // Integer part: longer (after stripping leading zeros) wins, else lexical.
    let a_i = a_int.trim_start_matches('0');
    let b_i = b_int.trim_start_matches('0');
    let by_int = a_i.len().cmp(&b_i.len()).then_with(|| a_i.cmp(b_i));
    if by_int != Ordering::Equal {
        return flip(by_int);
    }

    // Fraction: pad to equal length so "1.5" vs "1.45" compares digit by digit.
    let width = a_frac.len().max(b_frac.len());
    let pad = |s: &str| format!("{s:0<width$}");
    flip(pad(&a_frac).cmp(&pad(&b_frac)))
}
```

    // in `param_schema`. Dropping them would make the document describe a wider
