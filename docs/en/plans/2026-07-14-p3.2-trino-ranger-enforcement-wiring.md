# P3.2 Trino↔Ranger Enforcement Wiring — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make egret's provisioned Trino engines actually *enforce* the P3.2
tag-based masking/row-filter policies by wiring the (already-bundled) Trino
`apache-ranger` access-control plugin to egret's Ranger-Admin-compatible
`/service` download endpoints — then live-smoke masked-vs-clear on a real table.

**Architecture:** egret already serves the Ranger Admin download REST API
(`GET /service/plugins/policies/download/{svc}`, `GET /service/tags/download/{svc}`)
and, on engine provisioning, auto-creates a trino policy profile + a `<name>_tag`
tag service. The **only** missing piece is that the provisioned Trino pod has no
`access-control.properties` and no ranger plugin config file, so nothing consumes
those policies/tags. We add that config to the orchestrator's ConfigMap
templating, gated on the engine being bound to a profile. No plugin install is
needed — `trinodb/trino:470` already ships `/usr/lib/trino/plugin/apache-ranger/`.

**Tech Stack:** Rust (egret-orchestrator, egret-engine-mgmt, egret-engine-mgmt-api),
Trino 470 bundled `io.trino:trino-ranger` (Ranger 2.5 plugin), kind, kubectl.

## Background — spike findings (already verified live, 2026-07-14)

All confirmed against the running `demo2` engine in the `egret-engines` kind namespace:

1. **Plugin is present in the stock image**: `/usr/lib/trino/plugin/apache-ranger/`
   contains `io.trino_trino-ranger-470.jar` + `ranger-plugin-*-2.5.0.jar`. No install needed.
2. **Config contract (from `javap` on `RangerConfig.class`)** — `access-control.properties` keys:
   - `access-control.name=ranger`  ← factory name is the literal `ranger`
   - `ranger.service.name=<svc>`  ← `@Config("ranger.service.name")`, `@NotEmpty` ("Name of Ranger service containing policies to enforce")
   - `ranger.plugin.config.resource=<file,...>`  ← `@Config("ranger.plugin.config.resource")` ("List of paths to Ranger plugin configuration files")
   - `ranger.hadoop.config.resource=<file,...>`  ← optional; leave unset.
   - The plugin errors with `"ranger.service.name is not configured"` if missing; the service *type* is `trino`.
3. **Download paths match egret exactly**: the Ranger `RangerAdminRESTClient` GETs
   `{policy.rest.url}/service/plugins/policies/download/{serviceName}` and
   `{policy.rest.url}/service/tags/download/{tagServiceName}`. egret mounts
   `ranger_router()` at `/service` with routes `/plugins/policies/download/{service}`
   and `/tags/download/{service}` (`crates/egret-policy/src/ranger/routes.rs`). So
   `ranger.plugin.trino.policy.rest.url` = egret **base URL** (no suffix). The tag
   service name is discovered by the plugin from the `tagService` field egret
   already stamps on the trino profile config (`engines.rs:1482`).
4. **Auth**: egret's `require_bearer` (`crates/egret-policy/src/ranger/auth.rs`) is
   **anonymous when the token is empty** — explicitly designed for stock Ranger
   plugins that authenticate out-of-band. `RangerSettings.auth_token` defaults to
   `String::new()` (`egret-config/src/lib.rs:233`) and the running serve sets no
   token → anonymous. The bundled plugin has no simple bearer option, so we run
   anonymous for the smoke (surface is read-only). No code change needed here.
5. **Network**: a kind pod reaches the host egret via `host.docker.internal:8080`
   (resolved to 192.168.65.254; TCP OPEN). But egret currently bakes
   `engine_egret_url = http://localhost:8080` into provisioned catalogs
   (`engines.rs:292,298`) — wrong for kind pods (that's the pod's own localhost),
   which is why `demo2`'s warehouse showed 0 namespaces. The ranger URL must reuse
   the **same** `engine_egret_url`, and for the kind smoke that value must be
   `http://host.docker.internal:8080`.

```rust
/// Ranger tag/policy enforcement wiring (Access P3.2). `Some` when the engine is
/// bound to a policy profile; the orchestrator then templates
/// `access-control.properties` + `ranger-trino-security.xml` so the bundled
/// `apache-ranger` plugin polls egret's Ranger-Admin `/service` download API.
#[derive(Clone, Debug)]
pub struct RangerBinding {
    /// `ranger.service.name` — the bound trino profile's name.

}
```
