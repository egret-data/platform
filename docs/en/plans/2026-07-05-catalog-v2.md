# Catalog v2 — Connector-First + Per-Property Secrets — Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Rework catalogs to be connector-first (each connector a top-level choice, no "generic" wrapper), with per-property secret-or-value, over a comprehensive connector list.

**Architecture:** `kind` = connector name; `config = {properties, secretProperties}`. Backend `build_catalog_req` gets a uniform connector arm (+ per-property secret env vars + a compat shim for old rows). Frontend: expanded `connectorCatalog`, a new `SecretOrValueList` (per-row plaintext/secret toggle), and a reworked `CatalogForm` (connector picker + uniform property form).

**Branch:** `feat/engine-config-ui-remap`. **Spec:** `docs/en/specs/2026-07-05-catalog-v2-connector-first-per-property-secrets.md`.

---

## Conventions
- Backend from repo root; frontend from `frontend/`. Gates: backend `cargo fmt --all && cargo clippy -p egret-controlplane --all-targets -- -D warnings && cargo test -p egret-controlplane`; frontend `npm run typecheck && npm run lint && npm run test -- --run`.
- Conventional Commits, repo identity, one commit per task.
- **Guardrails:** connector catalog with only plaintext props renders identically to v1's generic path (connector.name + verbatim props). Old-shaped rows (v1 postgres/generic) still provision (compat shim). Secrets stored as uuids only; egret-warehouse credential still redacted.

## Task 1: Backend — uniform connector arm + per-property secrets

**Files:** `crates/egret-controlplane/src/engines.rs` (`build_catalog_req` ~601-711; `add_catalog` kind check ~1813; `CATALOG_KINDS` ~666).

- [ ] **Step 1:** Relax the kind whitelist. Change `add_catalog`'s `if !CATALOG_KINDS.contains(&b.kind.as_str())` guard to accept `egret-warehouse` OR any non-empty connector name (`b.kind` = a lowercase connector id). Keep rejecting empty kind. `CATALOG_KINDS` may stay for the frontend's benefit but is no longer the validation gate; update its comment.
- [ ] **Step 2:** Rewrite `build_catalog_req` so all non-`egret-warehouse` kinds go through ONE uniform arm. Replace the `postgresql`/`tpch`/`tpcds`/`generic`/`other =>` arms with:
```rust
_ => {
    props.insert("connector.name".into(), cat.kind.clone());
    // v2 shape: { properties: {..}, secretProperties: {prop: secret-uuid} }.
    // Back-compat shim for v1/older rows is applied first (see helper).
    let (plain, secrets) = catalog_props_and_secrets(cat);
    for (k, v) in plain {
        props.insert(k, v);
    }
    let mut n = 0;
    for (k, secret_id) in secrets {
        let var = format!("CAT_{env_prefix}_{n}");
        n += 1;
        props.insert(k, format!("${{ENV:{var}}}"));
        let val = st
            .secrets
            .resolve_plaintext(None, secret_id)
            .await
            .map_err(|e| CpError::BadRequest(format!("resolve secret: {e}")))?;
        env.insert(var, val);
    }
}
```
Keep the existing `"egret-warehouse" => { … }` arm verbatim before this `_` arm (match on `"egret-warehouse"` explicitly, uniform arm as `_`).
- [ ] **Step 3:** Add the helper `catalog_props_and_secrets(cat: &EngineCatalog) -> (Vec<(String,String)>, Vec<(String, Uuid)>)`:
  - **v2 shape** (`config.properties` object present): plain = all `config.properties` string entries; secrets = each `config.secretProperties` entry parsed as `(key, Uuid)` (skip invalid uuids). Ensure a key in both maps is treated as secret (secret wins) — or assume disjoint (frontend guarantees disjoint).
  - **Legacy generic** (`config.connectorName` present, no `config.properties`... actually old generic used `config.properties` too): if `config.secretProperty` + `cat.secret_ref` are set (old single-secret), add `(secretProperty, secret_ref)` to secrets and drop that key from plain; connector.name should be `config.connectorName` if present — BUT since kind is now the connector, prefer `cat.kind` unless kind=="generic" (old rows), in which case use `config.connectorName`. Handle: if `cat.kind == "generic"`, override the `connector.name` set in Step 2 by returning connectorName via a side channel — simplest: handle old generic INSIDE this helper by NOT relying on Step 2's `cat.kind` for connector.name. To keep Step 2 simple, special-case: if `cat.kind == "generic"`, set connector.name from `config.connectorName` (do this in the `_` arm: `let connector = if cat.kind=="generic" { config["connectorName"].as_str().unwrap_or(&cat.kind) } else { &cat.kind };`).
  - **Legacy postgres** (`cat.kind == "postgresql"` AND `config.host` present, no `config.properties`): reproduce v1's mapping (connection-url from host/port/database, connection-user, connection-password via `cat.secret_ref`). Return those as plain + the password as a secret.
  Implement the shim defensively; if unsure whether a row is legacy, prefer the v2 reading when `config.properties` exists.
- [ ] **Step 4:** Tests (self-skipping like existing, or pure where possible): (a) v2 connector with `properties` + two `secretProperties` → `connector.name==kind`, both plain props present, two distinct `${ENV:CAT_..}` + two env entries; (b) v2 connector with only `properties`, no secrets → verbatim, empty env (parity); (c) legacy generic row (connectorName + secretProperty + secret_ref) still renders as before; (d) legacy postgres row still renders `connection-url`/`connection-password=${ENV:..}`. Reuse the Task-19 test harness (real secrets backend, self-skip on no DATABASE_URL).

## Task 3: Frontend — `SecretOrValueList` (per-property secret-or-value)

**Files:** Create `frontend/src/routes/control-plane/config/SecretOrValueList.tsx`; base it on `KeyedPropertyList`.

- [ ] **Step 1:** Build a list like `KeyedPropertyList` (scoped `catalog`, `presentKeys`, "+ Add property" picker) but the VALUE column per row is EITHER a typed value (`PropertyField`/input) OR a secret `Select`, controlled by a per-row toggle button ("Use secret" ⇄ key icon). Props:
```ts
{
  catalog: TrinoProp[];
  catalogByKey: Record<string, TrinoProp>;
  // union of the two maps' keys drives the rows
  values: Record<string, string>;         // plaintext
  secrets: Record<string, string>;        // key -> egret secret id
  secretOptions: { id: string; name: string }[];  // from listSecrets()
  setValue: (key: string, value: string) => void;      // sets plaintext; also removes from secrets
  setSecret: (key: string, secretId: string) => void;  // sets secret; also removes from values
  remove: (key: string) => void;
}
```
A row is "secret mode" iff `key in secrets`. The toggle flips: value→secret (call `setSecret(key, "")`) / secret→value (call `setValue(key, "")`). Adding a catalog/custom key starts in value mode. Reuse `PropertyPicker` for adds.
- [ ] **Step 2:** `npm run typecheck && npm run lint`. Commit `feat(engine-catalog): SecretOrValueList editor`.
